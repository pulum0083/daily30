# 배당 인컴 설계기 — 컨텍스트 노트

작업 중 내린 결정과 근거를 계속 덧붙인다.

## 결정 1 — 배당주 + 커버드콜을 한 메뉴로 묶는다
사용자 목적(인컴)이 동일하고, 묶어야 "순수 배당 5% 안전 vs 커버드콜 12% 원금성 분배"의
**대조**를 보여줄 수 있다. 그 대조가 제품 핵심 가치라 따로 떼면 둘 다 평범한 리스트가 된다.
v1은 개별 배당주는 제외하고 ETF만 다룬다(데이터 정합·범위 관리).

## 결정 2 — 경쟁력은 기능 목록이 아니라 "정직 레이어"
인컴 목표 조합기, 종합과세 계산기는 단독으론 약하다(목표÷분배율은 누구나 함, 세금
계산기는 홈택스에 있음). 진짜 해자는 **커버드콜 원금성 분배를 까주는 것** — 아무도
정직하게 안 보여주는 영역. 세금 계산기도 조합에 통합("네 조합이 2,400만원 만든다 →
종합과세 대상 → 비중 조정")해야 가치가 산다. 단독 기능 나열은 지양.

## 결정 3 — 거래량 급증 메뉴는 드롭
홈 3카드 후보 중 하나였으나 사용자가 제외 결정(2026-06-13). 거래량은 수단이지 목적이
아니라 "왜"가 안 붙으면 노이즈. 3번째 카드는 배당 인컴 설계기로 확정.

## 결정 4 — 보유-입력 "트래커"는 접고, 랭킹(히어로)+단발 시뮬레이터(서포트)
프리셋 버튼 계산기 프로토(50/100/200/300만)가 "안 와닿는다"는 피드백. 다음 후보로 사용자가
"내 보유 종목 넣고 목표 넣고 계산" = 포트폴리오 트래커를 제안. 검토 결과 트래커 방향은 접음.
- 과밀: Snowball/Sharesight/Simply Safe Dividends, 한국 배당 트래커 앱·증권사앱이 이미 함.
- 마찰·저장: 수동 입력 이탈률 높음 + 더블샷은 로그인 없는 정적 서빙이라 포트폴리오 저장 불가
  (계정·백엔드 필요 → 아키텍처 붕괴).
- **SEO 루프 파괴**: 인터랙션 뒤 숨은 도구라 색인 페이지 0개. ETFNow 전략(영구 페이지 검색
  복리 루프)을 정면으로 거스르는 닫힌 루프 회귀.
- 해자 약화: 원금 침식 경고는 "사기 전"에 보여줘야 actionable. 이미 보유한 사람한텐 사후 통보.

그러나 "개인화가 구체성을 만든다"는 사용자 직관은 맞음. → 절충: **저장 안 하는 단발
시뮬레이터**로. 보유를 던져넣으면 원금성 경고가 "내 돈" 얘기가 되어 해자가 더 세지고(개인화),
갭 메우기 제안으로 랭킹/디스커버리로 환류시킴. 랭킹은 SEO 히어로로 유지. 프로토타입
(`flow-clickable.html` #income)에 이 버전으로 재구현 완료.

## 결정 5 — 1.2단 레이아웃 · 보유=주 단위 · 콤보박스 · ncai 디자인 시스템 (2026-06-13)
- **1.2단 구조**: 종목 상세와 동일한 `.grid`(1fr/360px). 메인=시뮬레이터, 사이드바=인컴 ETF
  전체(1조+). 랭킹이 좁아져 3줄 컴팩트 행(이름+뱃지 / 코드·순자산 / 분배·총수익·침식)으로 재설계.
- **보유 입력 = 주(shares)**: 금액(만원)→수량(주)로 변경. 인컴 = 수량 × 주가 × 분배율.
  유니버스에 `price` 추가. 사용자 요청("숫자 넣는 공간에 '주' 명시").
- **콤보박스(네이티브 select 폐기)**: 순자산 톱10 기본 노출 + 이름·코드 검색. 유니버스가
  커지면 select는 검색 불가라 콤보박스가 정석. US 직상장(JEPI/SCHD/QYLD)은 검색으로만 추가
  (톱10은 국내 1조+ 기준). onmousedown으로 선택(blur보다 먼저), onblur 150ms 지연 닫기.
- **디자인 시스템 = GronkOut/ncai-design-system**: 기존 목업이 이미 라이트모드 토큰과 거의
  일치(--primary #006eff, --ink #13151a 등). 인컴 화면에 시맨틱 색 정렬 — 건전 #00ae1a/#ecfeea,
  주의 #eb8e02/#fff9e3, 원금성 #f33942/#fff5f7. 카드 radius 16px(lg), 그림자 level-1, 타이포 weight
  600/500/400. 전체 목업 리팩터는 안 함(서피스 단위로만 적용).
- 프로토타입 검증 완료(콤보 톱10·검색·주 단위·사이드바 10행·KPI 갱신, 콘솔 에러 0).

## 결정 6 — 사이드바 랭킹 강화 + 인터랙션 3종 (2026-06-13)
- **사이드바 15행 + 랭킹 번호**: 분배율/건전성 정렬 결과를 톱15로 노출(`slice(0,15)`),
  행마다 순위 번호 prefix(1~3위는 갈색 채움 배지). 유니버스를 1조+ KR ETF 16종으로 확장
  (RISE 미국30년국채커버드콜·TIGER 미국나스닥100타겟데일리·PLUS 고배당주·TIGER 리츠부동산인프라
  ·KODEX 고배당 등 추가 — 전부 프로토 샘플값, v1 파이프라인이 실측 대체 예정).
- **타이틀 좌측 정렬**: `panel__h`가 flex 3자식(::before 바·텍스트·탭)을 `space-between`으로
  분배해 텍스트가 가운데로 밀리던 문제. `space-between` 제거하고 탭에 `margin-left:auto`.
- **갈아타기 제안(`sim-swap`)**: 보유 중 원금성 종목이 있으면 침식 최악 1종목을 골라, 최고
  분배율 건전(ok) ETF로 스왑 제안. 같은 평가금액 기준 월 인컴 변화까지 정직 표기("줄지만
  가격이 안 녹아 실질 안정적"). 침식 경고가 actionable 해짐.
- **콤보 키보드 ↑↓**: `comboKey()`로 ArrowDown/Up 하이라이트(`comboIdx`/`comboCur`), Enter 선택,
  Esc 닫기. 닫힌 상태에서 ArrowDown은 목록 열기.
- **사이드바 행 클릭 → 담기(`addFromRanking`)**: 행 onclick을 etf-detail 이동에서 시뮬레이터
  담기로 변경. 기본 100주(보유 중이면 +100주) + 해당 simrow 하이라이트·스크롤. 랭킹→시뮬레이터
  환류가 클릭 1번으로 성립.

## 발견 1 — 가격침식 프록시로 ROC 없이 해자 성립
네이버에 명시적 원금분배(ROC) 분해 데이터가 없어 처음엔 해자 구현이 막힐 줄 알았다.
그러나 `returnPerformanceList`(총수익)와 `dividend.dividendYieldTtm`(분배율)이 모두
있어, **총수익 − 분배율 = 가격 변화 프록시**로 침식을 드러낼 수 있다. ROC 분해 불필요.
- 실증: TIGER 미국30년국채커버드콜 분배율 13.02% vs 총수익 Y1 1.85% → 가격 −11%.
- 대조군: ACE 미국배당다우존스(순수 배당) 분배율 9.15% vs 총수익 35.42% → 건전.

## 발견 2 — 분배 데이터는 etfAnalysis 한 엔드포인트에 전부
AUM·분배율·분배 월·총수익·NAV성과·과세유형·보수·상장일이 모두
`m.stock.naver.com/api/stock/{code}/etfAnalysis` 하나에 들어있다. build_etf_exposure와
동일한 무인증 패턴. 분배 월(`dividendMonthThisYear`)이 있어 인컴 평탄화도 v1 가능.

## 발견 3 — 분배율 TTM은 신생 펀드에서 과소표시
TIGER 미국배당+7%프리미엄(458730)은 분배율 TTM 2.69%로 낮게 나왔다. 상장 2023-06이라
TTM 구간이 펀드 정책 변경/초기를 포함한 듯. **상장 1년 미만 또는 분배 정책 변경 펀드는
TTM이 forward 분배율을 왜곡**하므로 listedDate로 신뢰도 플래그 필요.
