# 밤사이 브리지 — 설계

작성일 2026-08-02 · 대상 화면 코스피 아침 브리핑(`web/briefings/{date}/kospi/index.html`)

## 배경·목적

`docs/analysis/2026-08-02-stockripple-benchmark.html`에서 StockRipple의 "국장 선반영 %p"를 벤치마크했다. 이 서비스는 §24 방지 룰에서 이미 "EWY 등락률은 같은 날 코스피 등락을 이미 반영한 값이라 신규 악재로 쓰면 이중 계상 — EWY를 근거로 쓸 땐 당일 코스피 등락률과 함께 제시해 중복분을 드러낸다"고 답을 적어뒀다. 이 기능은 그 답의 UI 구현이다.

- 무엇: 간밤 미국 정규장 등락과 한국 직전 마감 등락을 섹터 대표 종목으로 대칭 비교해 `%p` 차이(선반영/미반영)로 보여준다.
- 적용 범위: **코스피 아침 브리핑(07:25)에만.** 간밤 미국 vs 직전 한국 마감이라는 비교축은 이 시점에만 성립한다. 마감(16:25)은 한국이 이미 오늘 닫혀 있어 "간밤"이 없고, 미국 브리핑(21:15)은 한국이 이미 닫혀 다른 축(§26 프리마켓)이 필요해 범위 밖이다.
- LLM 미개입. 결정론적 계산 결과만 렌더한다 — §22~§29가 겪은 시제·방향·날조 계열 사고가 이 섹션에는 구조적으로 발생할 수 없다.

## 비교 축·집계 방식

- **개장 전 선행형**: 미국 = 간밤 정규장 등락(당일 07:25 기준 최신), 한국 = 직전 완료 세션(전일) 마감 등락. §24가 "발행 시각의 시장 국면이 곧 지금"이라 정한 원칙과 일치 — 07:25엔 한국도 미국도 이미 닫혀 있어 둘 다 "완료된 마지막 세션"이 정직한 비교 대상이다.
- **섹터 집계는 대표 종목 대칭.** 전 종목 단순평균은 중소형주 노이즈에 휘둘리고(§0 정합성 위반 소지), 시총 가중은 신규 수집이 필요해 범위가 커진다. `scripts/config/stock_universe.json`을 단일 소스로 쓴다 — 섹터당 미국은 대표 ETF 1개(있으면), 없으면 개별 벨웨더 평균. 한국은 섹터 대표 2종 평균.

| 섹터 | 미국 측 | 한국 측(대표 2종) |
| --- | --- | --- |
| 반도체 | SOXX | 삼성전자·SK하이닉스 |
| 전력기기 | GEV·VRT 평균 | HD현대일렉트릭·LS일렉트릭 |
| 방산 | ITA | 한화에어로스페이스·LIG넥스원 |
| 2차전지 | LIT | LG에너지솔루션·에코프로비엠 |
| 자동차 | TSLA·F 평균 | 현대차·기아 |
| 바이오 | XBI | 삼성바이오로직스·셀트리온 |
| 금융 | JPM·KBE 평균 | 삼성생명·KB금융 |
| 조선 | (미국 벨웨더 없음) | — |

조선은 원천 제외(8섹터 중 7개만 노출).

**⚠️ 재사용 금지 함정**: `fetch_data.py`에 이미 `SECTOR_FOCUS_STOCKS`라는 유사 테이블이 있다(중단된 `sector_focus` 섹션용, 2026-07-07 중단). 섹터 구성이 `stock_universe.json`과 다르다(전력기기·자동차·금융에 ETF 없음, 종목 조합도 다름). **이 테이블을 재사용하지 않는다** — 재사용하면 §20·§30이 반복 지적한 "같은 데이터의 이중 소스"가 또 생긴다. 밤사이 브리지는 `stock_universe.json`만 참조한다.

## 데이터 파이프라인

### 미국 측 — `fetch_data.py`에 신규 수집 추가

`fetch_kospi_data()`의 기존 `macro_tickers`(이미 NVDA·AAPL 등을 07:25에 `get_ticker_full()`로 받고 있음)와 동일한 방식으로 벨웨더 티커를 추가 수집한다. NVDA는 이미 있으므로 신규 추가는 12종: `MU, SOXX, GEV, VRT, ITA, LMT, ALB, LIT, TSLA, F, XBI, LLY, JPM, KBE`.

### 한국 측 — 신규 수집 없음

`web/data/stocks-snapshot.json`(전일 16:25 `build_stocks_snapshot.py`가 생성, 이미 대표 종목 `close`·`change_pct` 포함)을 그대로 읽는다.

### 신규 함수 `fetch_data.fetch_overnight_bridge(macro: dict, snapshot: dict) -> list[dict] | None`

순수 함수. 입력은 위에서 수집한 `macro`(미국 벨웨더 딕셔너리)와 `stocks-snapshot.json` 파싱 결과.

1. **스냅샷 신선도 검사**: `snapshot["generated_at"]`이 4일 이상 지났으면 `None` 반환 → 섹션 전체 생략. (§20 `_targets_data_is_stale`가 쓴 5일 버퍼와 같은 이유 — 스냅샷은 평일 16:25 1회 갱신이라 금요일 생성분을 월요일 07:25에 읽으면 이미 ~2.6일 지나 있다. 2~3일로 잡으면 매주 월요일 또는 3일 연휴 다음날 정상 데이터를 스테일로 오판한다. 4일이면 월요일은 통과하고, 최장 3일 연휴+주말 조합만 걸러진다.)
2. 섹터별로 위 표대로 미국·한국 평균 등락을 계산. 어느 한쪽이라도 값을 못 구하면(macro에 티커 없음, snapshot에 종목 없음) 그 섹터 행을 결과에서 제외 — 나머지 섹터는 정상 진행.
3. 남는 섹터가 0개면 `None` 반환.
4. 반환 스키마: `[{"sector": "반도체", "us_label": "SOXX", "us_change": 8.5, "kr_label": "삼성·하이닉스", "kr_change": 28.38, "gap_pp": 19.9}, ...]`. `gap_pp = kr_change - us_change`, 소수 1자리 반올림.
5. `latest_kospi.json`에 `overnight_bridge` 필드로 저장.

## 렌더링

### 신규 템플릿 `scripts/templates/sections/_overnight_bridge.html`

`market_data.html`과 같은 패턴 — Claude가 아니라 `generate_html.py`가 `overnight_bridge` 리스트를 직접 순회해 렌더한다(LLM 경유 없음, 산문 검증 게이트 대상 아님).

- 위치: `scripts/templates/briefings/kospi.html`에서 `_us_issues.html`(간밤 미국 시장 이슈) 렌더 직후, `prediction_strip`/`prediction` 앞. `{% if overnight_bridge %}` 가드.
- 섹터 행: `섹터명 | 미 {us_change}% ({us_label}) | 한 {kr_change}% ({kr_label}) | 선반영/미반영 {gap_pp}%p`. `gap_pp > 0`이면 "선반영", `< 0`이면 "미반영", 라벨 색은 `--up`(빨강)/`--dn`(파랑) — ncai 도메인 예외(§ 실적 캘린더 스펙과 동일 원칙) 그대로 적용, ncai semantic 팔레트 사용 금지.
- 좌측 컬러 액센트 바 금지(ncai 규칙). 강조는 `surface-soft` 톤 + 텍스트 굵기.
- 하단 고정 면책 문구: "선반영은 한국이 미국 평균보다 이미 더 크게 움직였다는 뜻, 미반영은 아직 못 따라갔다는 뜻입니다. %p는 두 시장 평균 등락률의 차이일 뿐 오늘 방향을 보장하지 않습니다. 조선은 대응 미국 지표가 없어 제외했습니다."

### `kospi.json` 설정

`sections_main`에 새 섹션 키 추가 불필요 — `_overnight_bridge.html`은 `_us_issues.html`처럼 config 목록이 아니라 kospi.html 템플릿에 직접 `{% include %}`로 하드코딩된다(현재 `_us_issues.html`·`_now_band.html`과 동일한 배선 방식).

## 미결 사항 (구현 계획에서 확정)

- `_overnight_bridge.html`의 정확한 include 위치는 실제 렌더된 kospi.html의 최신 섹션 순서(코스피 브리핑 위로카드 재구성 스펙 적용 후) 기준으로 재확인한다 — 두 스펙이 같은 템플릿을 건드리므로 구현 순서에 따라 diff 충돌 가능성이 있다.
- 벨웨더 티커 수집 실패 시 stderr 로그 포맷은 기존 `fetch_data.py` 관례(`[fetch_data] ... 수집 실패`)를 따른다.
