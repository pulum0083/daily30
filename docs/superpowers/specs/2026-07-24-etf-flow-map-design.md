# ETF 자금 지도 (홈 대시보드) — 설계

작성일 2026-07-24 · 대상 화면 `web/stocks/index.html` 홈(home-main 컬럼)

## 배경·목적

종목 대시보드 홈에서 밸류에이션 시그널 블록이 제거된 자리(home-main, 섹터 브라우저 아래)에 **ETF 자금 지도** 블록을 새로 넣는다. 홈엔 이미 "종목을 골라주는 랭킹"이 4개(특이 신호·거래량·섹터·주도주) 있어, 밸류에이션도 성격이 겹쳐 빠졌다. 그래서 이 블록은 종목 픽이 아니라 **"시장 전체의 돈이 어디로 몰리나"** 를 보여주는, 기존 랭킹과 완전히 다른 역할을 맡는다.

- 지표: 테마별 ETF **순수 자금흐름(설정/환매)**. 전 자산군(국내 주식 테마·해외·채권·원자재).
- 이 블록의 임무는 "돈의 방향". 그래서 가장 강한 시각 변수(타일 크기)를 정적 규모(AUM)가 아니라 **실제 움직인 자금(flow)** 에 배정한다.

부활 대상이 아닌 것: 죽은 자산으로 남은 `etf-rank` 화면(거래량/상승률 ETF 랭킹, 진입 링크 0건)과 `build_etf_exposure.py`(종목→패시브 노출도)는 이번 스코프와 무관하다. 이번 건은 성격이 다른 **신규 자금흐름 지도**다.

## 지표 정의 — 순자금흐름

네이버 ETF 목록 API(`finance.naver.com/api/sise/etfItemList.nhn`, 무인증, euc-kr)는 전 ETF(≈1150개)에 대해 `nowVal·changeRate·nav·marketSum(AUM,억원)·quant·amonut` 등을 당일 제공한다. 과거 좌수 히스토리는 없다.

- 추정 좌수 `shares ≈ marketSum(억원)×1e8 ÷ nav(원)`.
- 순자금흐름 `flow = (오늘 shares − N거래일 전 shares) × 오늘 nav` (원). 가격 효과를 벗겨낸 순수 설정/환매.
- **적응형 윈도우**: 가진 스냅샷 만큼, 최대 5거래일 누적. 배포 후 자동으로 자란다(아래 워밍업).

### 정합성 결정 (운영규칙 0)

- **AUM 300억 이상 ETF만** 집계한다. 소형 ETF는 `marketSum`이 억원 단위로 반올림돼 좌수 추정 노이즈가 커진다. 대형 위주로 제한해 정합성과 파일 크기를 함께 잡는다. (임계값은 튜너블.)
- **백필 불가**: 네이버는 현재 AUM만 준다. 스냅샷 시작 이전 기간은 소급 계산할 수 없다. → 워밍업 불가피. 억지 생성 금지.
- 테마 집계는 대형 ETF들이 지배하므로 개별 반올림 노이즈가 상쇄돼, 표시 단위(테마·억원)에서는 안정적이다.

## 워밍업 — 적응형 윈도우

스냅샷을 매일 1개씩 쌓아 차분한다. 배포 직후 상태 전이는.

| 스냅샷 수 | 표시 |
| --- | --- |
| 1개 (배포 당일) | flow 계산 불가 → **블록 숨김** |
| 2개 (이튿날) | "최근 1거래일" 누적 |
| 3~5개 | "최근 2~4거래일" (라벨 자동 증가) |
| 6개+ | "최근 5거래일" 고정 |

첫날 하루만 블록이 숨겨진다(보여줄 실데이터가 없는 정직한 처리). 규칙 위반 없이 이튿날부터 실데이터로 라이브된다.

## 데이터 파이프라인

### `scripts/build_etf_flows.py` (신규)

1. 네이버 ETF 목록 수집 → AUM 300억+ 필터 → 각 ETF `shares·nav·name·theme` 산출.
2. 오늘 스냅샷을 `data/etf_flow_history.json`(커밋)에 기록. **최근 7거래일치만 롤링 보관**(5일 윈도우 + 버퍼), 오래된 날짜 프룬.
3. 가장 오래된(최대 5거래일 전) 스냅샷과 차분해 ETF별 flow 산출.
4. 테마별 집계(순유입 합) + 각 테마 상위 ETF(개별 flow).
5. 출력 `web/data/etf-flows.json`.

### 테마 분류 (키워드 규칙)

이름 키워드 → 테마. 전 자산군 ~15개: 반도체·2차전지·자동차·방산·조선·바이오헬스·금융은행·인터넷게임·원자력전력·미국나스닥기술·미국S&P대형·중국신흥국·일본유럽·채권·금원자재·배당커버드콜. 어느 테마에도 안 잡히는 ETF(순수 파생·정체불명 catch-all)는 **지도에서 제외** — 이름 못 붙이는 "곳"은 그리지 않는다.

### 출력 스키마 `web/data/etf-flows.json`

```json
{
  "generated_at": "2026-07-24T18:05:00+09:00",
  "window_days": 5,
  "aum_floor_eok": 300,
  "coverage": { "etf_count": 412, "theme_count": 14 },
  "themes": [
    { "theme": "반도체", "flow_eok": 2340, "etf_count": 55,
      "top_etfs": [ { "code": "091160", "name": "KODEX 반도체", "flow_eok": 980 } ] }
  ]
}
```

- `flow_eok`: 억원 단위 순유입(양수 유입 / 음수 유출).
- `themes`는 |flow| 내림차순 전체를 담는다(집계된 모든 테마). `top_etfs`는 테마별 |flow| 상위 **5개**.
- 클라이언트는 |flow| **상위 ~10개 테마**를 타일로 노출하고, 나머지는 한 줄 요약으로 흡수(정확한 컷은 구현 계획에서 확정).

### 실행 — 전용 일일 워크플로우

- 평일 장 마감 후 ≈18:00 KST(순자산 EOD 확정 후) 1회. 휴장일 스킵(`holiday_check.py`). 주말·휴일 스냅샷 없음 → 거래일만 윈도우가 전진(금→월이 1스텝).
- **자기 파일만 커밋**: `web/data/etf-flows.json` + `data/etf_flow_history.json`. §18(파일 소유권 충돌) 방지 — 넓은 경로를 통째로 add 하지 않는다. 마케 발행 파이프라인과 독립.
- GHA native cron 지연 대비: 첫 스텝에서 `TZ=Asia/Seoul date +%u`로 평일 재확인(§10 패턴).

## 홈 블록 UI

위치: `home-main` 컬럼, `섹터별 대표 종목`(sbx-block) 아래(밸류에이션이 있던 자리).

- **트리맵 히트맵**: 타일 크기 = |flow|(움직인 자금), 색 hue = 방향(유입 빨강 `#E03131` / 유출 파랑 `#2775ED`), 색 세기 = |flow| 강도(크기와 강화). 큰 무버가 크고 진하게.
- 상위 무버만 타일로, 조용한 테마(작은 flow)는 아래 한 줄 요약("그 외 N개 테마는 이번 주 자금 이동이 크지 않았어요").
- 타이틀 "이번 주 자금 지도", 서브 "최근 {window_days}거래일 누적 · 실측 설정/환매 · 크기 = 움직인 자금". 도움말(?) 툴팁에 지표 정의(설정/환매·추정 방식·한계).
- 범례: 크기=움직인 자금 · 유입/유출 색 스케일.
- **타일 클릭 → 인라인 확장**: 그 테마 상위 ETF 몇 개(이름 + 개별 유입액). 새 페이지 없이 v1 완결.
- **신선도 가드(§20)**: `generated_at`이 5일(평일 갱신 + 주말·연휴 버퍼, §20 밸류에이션과 동일 기준)보다 오래되면 블록 숨김 + 콘솔/로그 경고. 수집이 조용히 죽어도 낡은 값이 진짜처럼 남지 않게(운영규칙 0). 달력 2일로 잡으면 월요일마다 금요일 데이터를 stale로 오판한다.
- 갱신: 페이지 로드 시 `etf-flows.json` 1회 fetch. 장중 폴링 없음(하루 단위 수치라 "장 마감·종가 기준" 정적 표시와 동일 성격).
- 반응형: 좁은 폭에서 트리맵 행이 1~2 타일로 줄고, 초소형 타일은 요약 줄로 흡수. 가로 스크롤 없이 읽히게.

구현 위치: 블록 렌더러는 `web/assets/stocks-home.js`(기존 홈 위젯들과 동일 패턴), 스타일은 `web/assets/stocks-home.css`.

- 죽은 `etf-rank` 화면 부활 및 테마 타일 클릭→필터 연결.
- ETF 상세 페이지.
