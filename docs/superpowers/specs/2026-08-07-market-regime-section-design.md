# 시장의 큰 흐름 (국면) 섹션 — 디자인 스펙

## 배경 · 목표

종목 시그널 홈에 **"몇 달 단위의 큰 흐름"**을 한 눈에 보여주는 영역을 만든다. 답해야 할 질문은 하나다 — **"지금 장을 끌고 있는 게 무엇이고, 그게 바뀌는 중인가."**

발단이 된 사용자 관찰: *"5-6월엔 메모리 반도체 중심의 장이었고 빅테크·소프트웨어가 약세였는데, 7월 들어 빅테크가 다시 살아나고 다우·SCHD 같은 배당·방어주가 강세다."* 이 서술이 실측으로 성립하는지 먼저 검증했고(성립함), 그 판정을 **규칙으로 재현**하는 것이 이 섹션의 본질이다.

**지금 홈에는 이 시간축이 없다.** 전 위젯이 오늘~이번 주 단위다.

| 블록 | 시간 스케일 |
| --- | --- |
| 장중 이슈 스트립 | 30분 |
| 코스피 주도주 | 실시간 |
| 상승 모멘텀 종목 | 오늘 |
| 섹터별 대표 종목 | 실시간 30초 |
| 이번 주 자금 지도 | **5거래일 (현재 최장)** |
| ETF 신호 · 특이 신호 | 당일 · 2분 |

즉 이 섹션은 기존 위젯 사이에 끼는 게 아니라 **없던 시간 층을 하나 추가**하는 것이다.

## 배치

**코스피 주도주 블록 바로 아래.** 읽는 순서가 `장중 이슈 → 코스피 주도주 → 큰 흐름 → 개별 종목`이 되어, 위젯들이 "이 국면 안에서의 오늘"로 읽힌다.

`#home` 안, `home-cols` 위쪽 전폭 영역에 둔다(섹터별 대표 종목 블록과 같은 취급).

## 데이터

### 소스

**Yahoo 일봉 하나만 쓴다.** 새 벤더도 새 API 계약도 없다.

`scripts/build_stocks_snapshot.py`가 이미 매일 US 심볼 약 40개를 `period="400d"`로 받아 `spark20`(20봉)·`ma200`만 남기고 **380봉을 버리고 있다.** 같은 경로를 재사용하면 6개월 히스토리는 백필 한 번으로 끝난다.

> **왜 자금 흐름이 아니라 수익률인가.** ETF 자금 흐름(`data/etf_flow_history.json`)은 `build_etf_flows.py`의 `KEEP_DAYS = 7`이 계속 잘라내고 있고, 삭제된 스냅샷은 git에도 없다(`git log --diff-filter=D`로 확인). **과거를 복구할 방법이 없다.** 지금 상한을 올려도 오늘부터 쌓일 뿐이라, 몇 달짜리 국면 판정에는 쓸 수 없다. 수익률·상대강도는 백필이 되므로 그쪽으로 간다.

### 산출물

`web/data/market-regime.json` — 하루 1회 갱신.

```jsonc
{
  "generated_at": "2026-08-07T16:31:00+09:00",
  "session_date": "2026-08-07",     // 실제 마지막 봉 날짜. 없으면 생략(§0)
  "window_days": 126,
  "state": "swap",                   // swap | lead | none
  "headline": "주도주가 메모리 반도체에서 AI 인프라, 가치 경기민감으로 넘어가는 중이에요",
  "regime_since": "2026-06-24",      // 현재 국면 시작일
  "baskets": [
    { "key": "memory", "name": "메모리 반도체", "scope": "global",
      "cum": 89.4, "peak": 142.6, "gap": -53.2, "is_high": false,
      // spark: 창을 주 1회로 샘플링한 누적수익률 26개. 카드의 미니 곡선 전용
      "spark": [0.0, -3.2, 12.0, /* … 26개 */ 89.4],
      "members": ["MU","SOXX","DRAM"], "n_used": 2 }
  ],
  "korea": { "semi": 51.2, "rest": -11.2, "gap": 62.4 }
}
```

### 바스켓 (7개)

**글로벌 5 — 헤드라인은 이 5개에서만 뽑는다.**

| key | 이름 | 구성 |
| --- | --- | --- |
| `memory` | 메모리 반도체 | MU, SOXX, DRAM |
| `ai_infra` | AI 인프라 | NVDA, MSFT, AMZN, AVGO |
| `consumer_platform` | 소비 플랫폼 | AAPL, GOOGL, META |
| `dividend_defensive` | 배당 방어 | SCHD, XLP, XLU |
| `value_cyclical` | 가치 경기민감 | IWD, XLF, XLE |

**한국 2 — 헤드라인에 쓰지 않고 read-through 줄 전용.**

| key | 이름 | 구성 |
| --- | --- | --- |
| `kr_semi` | 한국 반도체 | 005930.KS, 000660.KS |
| `kr_rest` | 한국 그 외 | 305720.KS, 449450.KS, 091170.KS, 091180.KS |

**빅테크를 AI 인프라 / 소비 플랫폼으로 쪼갠 이유.** 6종을 한 덩어리로 두면 7월이 **+4.9%**로 밋밋해진다 — MSFT +20.9%와 META −9.2%가 상쇄되기 때문이다. 쪼개면 AI 인프라 **+10.1%** vs 소비 플랫폼 **−1.9%**로 **12.0%p** 벌어져 실제 신호가 드러난다. 사용자가 관찰한 "7월 빅테크 부활"은 전자에서만 성립한다.

**한국을 헤드라인에서 뺀 이유.** 한국 반도체는 진폭이 글로벌 바스켓보다 훨씬 커서(정점 대비 −90%p 수준) 항상 "가장 크게 식은 것"과 "누적 1위"를 동시에 차지한다. 포함시키면 5개 국면 전부 주어가 "한국 반도체"가 되어 한·미 연결이라는 목적이 깨진다(실측으로 확인).

**바스켓 정의는 `scripts/config/regime_baskets.json`에 둔다.** `stock_universe.json`과 합치지 않는다 — 그쪽은 종목 상세 페이지용 벨웨더 집합이고 이쪽은 국면 판정용이라 목적·구성이 다르다(SCHD·XLP·IWD는 벨웨더가 아니다). 다만 겹치는 티커(NVDA·MU·SOXX 등)가 있으므로 **두 파일 헤더에 서로를 가리키는 주석을 남긴다.**

### 계산

- **창**: 126영업일 롤링. 각 시점에서 그 창의 첫날을 100으로 한 누적수익률.
- **바스켓 값**: 구성 종목 누적수익률의 **단순평균**(동일가중). 시총가중 안 씀 — NVDA 하나가 바스켓을 지배하면 쪼갠 의미가 사라진다.
- **결측 처리**: 창 시작일에 데이터가 없던 종목은 그 창의 평균에서 **제외**한다. `DRAM`이 2026-04-02 상장이라 실제로 발생하는 케이스다(이 처리를 안 넣으면 교집합이 비어 전체가 죽는다 — 설계 중 실제로 겪음). `n_used`로 몇 개가 쓰였는지 산출물에 남긴다.
- **한국 거래일 정렬**: 기준 캘린더는 미국 거래일(가장 촘촘). 한국 종목은 해당일 값이 없으면 직전 거래일 종가를 쓴다.

## 국면 판정

### 상태 3종

| 상태 | 조건 | 화면 |
| --- | --- | --- |
| `swap` 교체 | 식은 바스켓 **있고** 신고점 바스켓 **있음** | 좌우 2단 |
| `lead` 지속 | 신고점 바스켓만 있음 | 한 장 |
| `none` 무주도 | 신고점 바스켓 없음 | 한 장 |

### 임계값

| 항목 | 값 |
| --- | --- |
| 식음 | 정점 대비 **−15%p** 이상 |
| 신고점 | 정점 대비 **−3%p** 이내 |
| 히스테리시스 | 최근 **5일 중 3일** 이상 조건 충족 |
| 최소 국면 길이 | **10영업일**. 미만이면 직전 국면에 흡수 |

**이 값들은 375영업일 백테스트로 골랐다. 감으로 정한 게 아니다.**

첫 시도(신고점을 "정확히 정점"으로, 히스테리시스 없음)는 **375일 중 75번 상태가 뒤집혔다** — 평균 5일마다 카드 모양이 1단↔2단으로 바뀐다. 신고점 판정이 하루만 밀려도 깨지기 때문이다.

| 설정 | 교체 | 지속 | 무주도 | 전환 | 평균 지속 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 신고점 0.5%p · 히스테리시스 없음 | 17.1% | 51.2% | 31.7% | **75회** | 4.9일 |
| 신고점 3%p · 5일 중 3일 · 최소 10일 | 32.8% | 52.0% | 15.2% | **8회** | 41.7일 |
| **위 + 헤드라인 글로벌 한정** | — | — | — | **4회** | **75.0일** |

### 히스테리시스는 상태가 아니라 판정 입력에 건다 (중요)

**설계 중 발견한 버그다. 재발하기 쉬우니 이유를 남긴다.**

처음엔 일별 상태를 계산한 뒤 "5일 유지되어야 전환"으로 후처리했다. 그랬더니 이런 게 나왔다.

```
2026-06-30  [교체]  "주도주가 한국 반도체에서 로 넘어가는 중이에요"
                                              ↑ 비어있음
```

상태는 히스테리시스로 "교체"가 유지되는데, **그날 데이터엔 신고점 바스켓이 없어서** 문구를 만들 재료가 없다. 상태 판정과 문구 생성이 서로 다른 데이터를 본 것이다.

**해결**: 히스테리시스를 판정 **입력**에 적용한다. "최근 5일 중 3일 이상 식음 조건을 만족한 바스켓 집합", "최근 5일 중 3일 이상 신고점이었던 바스켓 집합"을 먼저 구하고, 상태 판정과 문구 생성이 **둘 다 그 집합에서** 재료를 가져간다. 그러면 상태가 있으면 재료도 반드시 있다.

## 문구

**LLM을 쓰지 않는다.** 계산값 두 개로 템플릿을 채운다.

| 상태 | 템플릿 |
| --- | --- |
| `swap` | `"주도주가 {A}에서 {B}{으로/로} 넘어가는 중이에요"` |
| `lead` | `"{C} 주도가 이어지고 있어요"` |
| `none` | `"뚜렷한 주도주가 없어요"` |

슬롯 정의 (정렬 기준을 명시한다 — 구현이 갈리지 않도록):

| 슬롯 | 대상 | 정렬 | 개수 |
| --- | --- | --- | --- |
| `A` | 식음 집합 | `gap` **오름차순** (가장 많이 내려온 것) | 1개 |
| `B` | 신고점 집합 | `cum` **내림차순** (누적 높은 순) | 최대 2개, `, `로 연결 |
| `C` | 글로벌 5개 전체 | `cum` **내림차순** | 1개 |

동점이면 `regime_baskets.json`의 선언 순서를 따른다(결정론 보장).

### 규칙

- **국면 단위로 한 번 확정한다.** 같은 국면 안에서는 문장이 바뀌지 않는다. 매일 문장이 미묘하게 달라지면 국면이라는 개념 자체가 흐려진다. 국면 안에서 재료가 유효한 가장 최근 날짜의 값으로 문구를 만들고 그 국면 내내 유지한다.
- **조사 분기.** 받침 유무로 `으로/로`를 고른다. 종성이 없거나 ㄹ이면 `로`, 아니면 `으로`. (검증 전 `"가치 경기민감로"`가 나왔다.)
- **바스켓 이름에 `·`를 쓰지 않는다.** 목록 구분자와 충돌해 `"가치·경기민감·배당·방어"`가 한 덩어리로 읽힌다. 이름은 `가치 경기민감`처럼 공백으로, 목록 구분자는 `, `로 한다.
- **read-through 줄은 별도.** `"한국은 반도체 {a}% vs 그 외 {b}% — 격차 {|a−b|}%p"`. 격차가 요점이므로 격차를 굵게 낸다.

### 검증 기준

375영업일 백테스트에서 **문구 생성 실패 0건**이어야 한다. 하나라도 `None`이 나오면 판정과 재료가 어긋난 것이므로 구현 오류다.

## 레이아웃

목업 3안(주도주 교체판) 확정. 카드 헤더는 기존 `.block__h` 규격을 따르고, 기준일 표기는 **`.ds-asof`를 쓰지 않는다** — 이 데이터는 하루 1회 스냅샷인데 `.ds-asof`는 장중에 "오늘 실시간"으로 바뀌어 없는 갱신을 광고하게 된다(섹터 화면 `secAsOfLabel`과 같은 이유, §10).

### `swap` — 좌우 2단

```
🌊 시장의 큰 흐름                      최근 6개월 · 8/7 기준
─────────────────────────────────────────────────────
주도주가 메모리 반도체에서
AI 인프라, 가치 경기민감으로 넘어가는 중이에요
6개월 누적 기준 · 6/24부터

┌──────────────────┐      ┌──────────────────┐
│ 식는 중           │  →   │ 뜨는 중           │
│ 메모리 반도체      │      │ AI 인프라  [6개월 최고]│
│ 정점 +142.6%      │      │ 누적 +17.2%       │
│  → 지금 +89.4%    │      │ ∿ 스파크라인       │
│ ∿ 스파크라인       │      │ 가치 경기민감 [6개월 최고]│
└──────────────────┘      └──────────────────┘

🇰🇷 한국은 반도체 +51.2% vs 그 외 −11.2% — 격차 62%p
```

### `lead` · `none` — 한 장

좌우 2단을 접고 헤드라인 + 1위 바스켓 스파크라인 + 한국 read-through 줄만 남긴다.

**"해당 없음"으로 칸을 비우지 않는다.** 빈 칸이 매일 뜨면 고장으로 보이고 채우고 싶은 압력이 생긴다. **레이아웃 자체가 바뀌는 것이 "지금은 교체 국면이 아니다"라는 정보다.**

### 색

한국 관례를 따른다 — 상승 빨강(`--up`), 하락 파랑(`--dn`). "식는 중"은 파랑 계열, "뜨는 중"은 빨강 계열 박스.

### 반응형

모바일에서 좌우 2단은 **상하 2단**으로 접힌다. 화살표 `→`는 `↓`로 바뀐다.

## 파이프라인

`kospi-close-briefing` 잡(16:25 KST)에 스텝을 얹는다.

```
fetch_closing_kospi → … → build_stocks_snapshot → build_market_regime ← 신설
```

- `timeout-minutes: 5`, `continue-on-error: true` — 이 섹션은 브리핑 발행에 필수가 아니다. 실패하면 직전 JSON이 남고 다음 거래일에 정상화된다(§21).
- 커밋 대상은 `web/data/market-regime.json` **한 파일만**. 넓은 경로를 `git add` 하지 않는다(§18).

## 신선도 가드

`generated_at`이 **5일**보다 오래되면 섹션을 **표시하지 않고** 로그에 경고를 남긴다. 목표주가 섹션의 `_targets_data_is_stale()`과 같은 처방이다(§20).

수집이 조용히 죽었을 때 "낡은 국면이 계속 진짜처럼 보이는" 상태가 §20에서 3주간 실제로 벌어졌다. 국면은 몇 주 단위라 낡아도 그럴듯해 보여서 더 위험하다.

## 테스트

**순수 함수 단위 (pytest)**

- `cum_returns()` — 결측 종목 제외, `n_used` 정확성, 창 시작 결측 시 제외
- `basket_state()` — 3상태 판정, 임계 경계값(정확히 −15.0 / −3.0)
- `apply_hysteresis()` — 5일 중 3일 규칙, 창이 5일보다 짧을 때
- `absorb_short_runs()` — 10일 미만 흡수, 첫 구간은 흡수 대상 아님
- `josa()` — 받침 있음/없음/ㄹ 종성
- `headline()` — 3종 템플릿, 구분자, **재료 없을 때 `None` 반환**

**회귀 (실데이터 리플레이)**

- 375영업일 백테스트에서 **문구 생성 실패 0건**
- 2026-04-10 ~ 06-23이 `lead`, 2026-06-24 이후가 `swap`으로 판정되는지 — 사용자가 관찰한 국면과 규칙이 독립적으로 일치했던 결과의 회귀 가드
- 전환 횟수가 375일 기준 **15회 이하** (그 이상이면 카드가 깜빡인다는 뜻)

**프런트 (node --test)**

- `swap`/`lead`/`none` 각각의 DOM 렌더
- 신선도 가드 발동 시 섹션 미표시
- `session_date` 없을 때 기준일 표기 생략

## 안 하기로 한 것

- **자금 흐름 기반 판정** — 히스토리가 7일에서 잘려 복구 불가.
- **LLM 서술** — 템플릿으로 충분하고, §22·§25·§28·§29가 전부 LLM 서술 사고였다.
- **예측·추천 문구** — "새 주도 후보", "지금 사야 할" 류 금지. `"6개월 최고"`처럼 **사실 진술**만 쓴다.
- **장중 갱신** — 하루 1회. 국면은 몇 주 단위라 장중 갱신에 의미가 없고, 실시간처럼 보이면 §10 위반이다.
- **바스켓 사용자 커스터마이징** — 요청 없음.

## 열린 항목

- **한국 read-through 기간.** 지금은 카드 전체와 같은 6개월 창을 쓴다(일관성). 그래서 `+275.5%` 같은 큰 수가 나올 수 있다 — 실측이지만 커 보인다. 구현하며 화면에서 확인하고, 부담되면 격차만 남기고 절대수치를 빼는 쪽으로 조정한다.
- **바스켓 구성 종목 재검토.** 초기값은 설계 과정에서 고른 것이라 운영하며 조정될 수 있다. 조정 시 백테스트를 다시 돌려 전환 횟수가 기준(375일당 15회 이하) 안에 있는지 확인한다.
