# 예측 성적표 — "항상 상승" 기준선 병기 · 디자인 스펙

## 배경 · 목표

코스피 브리핑의 **"우리 성적표" 카드**는 지금 적중률만 보여준다. `누적 80건 65%`가 잘한 것인지 못한 것인지 판단할 근거가 화면에 없다.

**코스피는 오르는 날이 더 많다.** 채점된 80건 중 실제 상승일이 50건이라, 매일 "상승"이라고만 답해도 62%를 맞힌다. 즉 우리 65%의 실질 우위는 **+3%p**다. 이 사실이 화면에 없으면 65%가 실제보다 훨씬 좋은 성적으로 읽힌다.

**목표는 하나다 — 적중률 옆에 "아무것도 안 했을 때의 성적"을 나란히 두어, 우리 숫자가 무엇 대비 좋은 것인지 스스로 말하게 한다.**

이 스펙은 표시(display)만 다룬다. 예측 모델·채점 기준은 건드리지 않는다.

## 실측 (2026-08-11 기준)

`data/briefings.json`, 채점 완료된 코스피 예측 80건(2026-04-07 ~ 08-05).

| 구간 | 우리 적중률 | 기준선 | 차이 |
| --- | --- | --- | --- |
| 최근 15건 | 73% (11/15) | 53% (8/15) | +20%p |
| 누적 80건 | 65% (52/80) | 62% (50/80) | **+3%p** |

월별로 보면 초기 두 달은 기준선에 **졌다**.

| 월 | n | 우리 | 기준선 | 차이 |
| --- | --- | --- | --- | --- |
| 4월 | 16 | 69% | 75% | **−6%p** |
| 5월 | 18 | 67% | 72% | **−5%p** |
| 6월 | 21 | 62% | 62% | 0%p |
| 7월 | 22 | 64% | 45% | +19%p |
| 8월 | 3 | 67% | 67% | 0%p |

누적 +3%p가 왜 그렇게 낮은지를 이 표가 설명한다. 4·5월은 상승 드리프트가 강해 기준선 자체가 70%대였고, 우리는 그걸 못 넘었다. 7월은 상승/하락이 갈리는 장이라 우리 우위가 제대로 드러난다.

**이 표를 그대로 노출한다.** 카드 CTA 문구가 "틀린 날까지 전부 공개해요"인데, 기준선에 진 달을 감추면 그 약속과 어긋난다.

## 기준선의 정의

```
기준선(구간) = (구간 내 실제 상승일 수) / (구간 내 채점 건수) × 100
```

- **대상은 우리 적중률과 정확히 같은 표본이다.** `is_correct != null`인 코스피 항목만. 미채점 항목이 한쪽에만 섞이면 비교가 무의미해진다.
- 상승 판정은 기존 채점 로직을 그대로 따른다 — `check_accuracy.classify_direction_correct()`가 `change_pct >= 0`을 상승으로 보므로, 기준선도 `actual_direction == "상승"` 필드를 그대로 센다. **새로운 판정 규칙을 만들지 않는다.**
- 의미는 "매일 상승이라고만 답하는 무지성 예측기의 성적"이다.

### 표시 값의 자기정합성

차이(`+20%p`)는 원본 실수의 차이가 아니라 **화면에 뜬 반올림값끼리의 차이**로 계산한다.

```
edge = round(our_pct) - round(base_pct)
```

사용자가 `73 − 53`을 암산했을 때 표시된 `+20%p`와 어긋나면 안 된다. 실수 차이를 따로 반올림하면 경계에서 1%p 어긋날 수 있다.

## 계산 위치

`build_scorecard()`([scripts/generate_html.py:1092](../../../scripts/generate_html.py))에만 추가한다. 이 함수가 이미 `scored` 리스트와 월별 집계를 만들고 있으므로 그 위에 얹는다.

**`accuracy-summary.json`(푸터 트러스트 스트립)에는 넣지 않는다.** 소비처가 하나뿐이면 §30이 경고한 "판정 로직 이중 구현"이 애초에 발생하지 않는다. 한 줄짜리 푸터 각주에 `+3%p`를 박아두면 맥락 없이 "우리 별로네"만 남는 것도 이유다.

### 신설 함수

```python
def _baseline_pct(rows: list) -> int:
    """구간 내 실제 상승일 비율(%). 기준선 = 매일 '상승'이라고만 답했을 때의 적중률."""

def _edge_cls(edge: int) -> str:
    """우위 폭(%p) → 게이지 채움 색 클래스. good | flat | bad."""
```

둘 다 순수 함수로 분리한다 — 파일 I/O 없이 테스트할 수 있어야 한다.

## 카드

`_scorecard.html`의 `최근 15건` / `누적 N건` 두 칸 **아래에만** 게이지를 붙인다. `적중일 평균` 칸은 대응하는 기준선이 없으므로 그대로 둔다.

```
┌──────────┬──────────┬──────────┐
│   73%    │   65%    │   3.5%   │
│ 최근 15건 │ 누적 80건 │ 적중일 평균│
│ ▬▬▬▬│▬▬  │ ▬▬▬▬▬│▬ │          │
│ 기준선 53% │ 기준선 62% │          │
└──────────┴──────────┴──────────┘
  ▬ 우리 적중률   │ 항상 "상승" 기준선
```

- 막대 채움 길이 = 우리 적중률(%), 세로선 위치 = 기준선(%). 둘 다 0~100을 그대로 width/left %로 쓴다.
- 막대 아래 `기준선 N%` 캡션(9px).
- 카드 하단(막대 밖)에 **범례 한 줄** — `▬ 우리 적중률` / `│ 항상 "상승" 기준선`. 게이지가 두 개라 캡션만으로는 세로선의 의미가 전달되지 않는다.

### 채움 색 — 우위 폭 3단계

| 우위 | 색 | 근거 |
| --- | --- | --- |
| ≥ +10%p | 초록 `#16A34A` | 유의미하게 앞섬 |
| −10 ~ +10%p | 회색 `#9CA3AF` | 사실상 차이 없음 |
| ≤ −10%p | 빨강 `var(--up)` | 기준선에 유의미하게 짐 |

**경계를 0%p로 두지 않는 이유** — 최근 15건 기준으로 1건이 6.7%p다. 한 자릿수 차이는 표본 노이즈이고, +3%p를 초록으로 칠하면 없는 우위를 주장하는 셈이 된다. 현재 누적 +3%p는 회색이 맞다.

## 모달

기존 `scorecard-modal` 안에 두 가지를 추가한다. "최근 예측 결과" 목록은 **변경하지 않는다.**

### ① 최상단 설명 블록

```
같은 기간 매일 "상승"이라고만 답하면 최근 15건 53%, 누적 62%를 맞혀요.
코스피가 오르는 날이 더 많기 때문이에요. 그래서 적중률만으로는 잘한 건지
알 수 없고, 이 기준선을 얼마나 넘었는지가 진짜 성적이에요 —
우리는 +20%p · +3%p였어요.
```

"기준선"이라는 낯선 단어를 그 자리에서 정의하는 역할이다. 카드의 범례가 못 하는 일을 여기서 한다.

### ② 월별 적중률 행에 기준선 컬럼

기존 `sc-mrate__row` 오른쪽에 `기준 N%` 텍스트 컬럼을 붙인다. 위 실측 표대로 4·5월이 마이너스로 노출된다.

섹션 제목에 `(오른쪽 = 기준선)` 보조 라벨을 단다.

**월별 막대 색은 기존 규칙을 그대로 둔다** — `cls()`가 절대 적중률(≥70 good / ≥50 mid / 그 외 bad)로 칠하고 있고, 이걸 우위 폭 기준으로 바꾸면 카드 게이지와 다른 의미의 색이 같은 팔레트로 섞인다. 월별 행에서 기준선은 **숫자로만** 전달한다.

**표본이 적은 달도 그대로 표시한다.** 8월은 n=3이지만 기존 카드가 이미 그 달을 보여주고 있고, 이번 변경으로 노출 범위를 바꾸지 않는다(§3 외과적 수정). n 표시 추가는 이 스펙 범위 밖이다.

## 범위 밖 — 신뢰도(confidence)

신뢰도 표기는 **이번 작업에 포함하지 않는다.**

캘리브레이션이 실제로 깨져 있는 것은 확인했다 — 60%대 예측이 64% 적중인데 **70%대는 55%로 오히려 낮다**(80%대는 77%). 단조증가가 아니라 현재 신뢰도는 정보라기보다 노이즈에 가깝다.

다만 이건 `prediction_strip.html`의 `신뢰도 {{ confidence }}%`를 건드리는 **별개 화면**이라, 같은 커밋에 섞으면 변경 단위가 흐려진다(§12). 기준선 작업이 끝난 뒤 별도 건으로 다룬다.

## 테스트

`scripts/test_scorecard_baseline.py` 신설. 기존 `scripts/test_*.py` 관례(모듈 직접 import, 평문 `assert`)를 따르고 CI의 `python3 -m pytest scripts/ -q`에 자동으로 포함된다.

| # | 케이스 | 대상 | 검증 |
| --- | --- | --- | --- |
| 1 | 기준선 기본 계산 | `_baseline_pct` | 상승 3 / 하락 2 → 60% |
| 2 | 미채점 항목 제외 | `_baseline_pct` | `is_correct: None`이 섞여도 채점분만 센다 |
| 3 | 빈 리스트 | `_baseline_pct` | 0으로 나누지 않는다 |
| 4 | 색 경계값 | `_edge_cls` | +10 초록 / +9 회색 / −9 회색 / −10 빨강 |
| 5 | 반올림 자기정합성 | `build_scorecard` | 표시된 `edge == 표시된 our − 표시된 base` |
| 6 | 월별 기준선 | `build_scorecard` | 4·5월이 음수 우위로 나온다 |
| 7 | 표본 5건 미만 | `build_scorecard` | 빈 dict 반환(기존 가드 회귀 방지) |

5~7번은 `build_scorecard()`가 `DATA_DIR / "briefings.json"`을 직접 읽으므로 **`monkeypatch.setattr(generate_html, "DATA_DIR", tmp_fixture_dir)`** 로 픽스처를 주입한다. 실파일을 읽으면 다음 채점 때 숫자가 바뀌어 테스트가 깨진다 — **고정 숫자를 실데이터에 기대지 않는다.**

픽스처는 위 실측 표를 재현하는 최소 항목만 담은 별도 JSON으로 테스트 파일 안에서 생성한다(별도 파일을 커밋하지 않는다).
