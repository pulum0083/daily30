# 종목 홈 하단 재설계 — 신호 분류 규칙 정의

작성 2026-06-27. 프로토타입: [docs/prototypes/2026-06-27-stock-home-signals.html](../../prototypes/2026-06-27-stock-home-signals.html)

종목 대시보드 홈(`web/stocks/index.html`) 하단의 범용 랭킹 6블록(거래량/상승/하락 톱 + ETF 거래량/상승/하락 톱)을 두 개의 해석형 섹션으로 재설계한다.

- **A. 오늘의 특이 신호** — 거래량/상승/하락 톱 3블록 대체. 교차 신호 큐레이션 + 규칙 기반 한 줄 해석.
- **B. ETF로 읽는 시황** — ETF 3블록 대체. 중립 톤 시황 해석 카드.

섹터별 보기 칩은 그대로 유지한다(네비게이션이라 손대지 않는다).

> **데이터 정합성**: 모든 수치는 생성 시점 실측만 사용한다. 신호 판정에 필요한 값(거래량 평균·수급·신고가·거래대금)을 못 구하면 해당 신호 뱃지·행을 생략한다. LLM 추론·하드코딩 금지. [SERVICE_RULES.md 운영규칙 0](../../SERVICE_RULES.md) 준수.

## A. 오늘의 특이 신호

### 신호 축 정의 (5종)

| 축 | 판정 조건 | 임계값 | 데이터 소스 | 뱃지 |
| --- | --- | --- | --- | --- |
| **역행** (counter-trend) | 종목 방향이 시장(코스피) 방향과 반대 AND 아웃퍼폼 | `sign(stock_pct) ≠ sign(kospi_pct)` AND `\|stock_pct − kospi_pct\| ≥ 3.0%p` | 종목 등락률 = 실측 종가 기준, 코스피 등락률 = `/api/kospi-live` | 🔵 역행 상승 / 역행 선방 |
| **투매** (capitulation) | 거래량 급증 + 급락 + 매도 수급 | `vol/vol_avg20 ≥ 1.5` AND `stock_pct ≤ −3.0%` AND (외국인 OR 기관 순매도) | 거래량·평균 = 스냅샷 `vol_avg20`, 수급 = 일별 투자자별 순매수 | 🔥 거래량 ×N 급증 + 🌏/🏛️ 순매도 |
| **거래대금 쏠림** | 거래대금 코스피 상위 | 거래대금 순위 ≤ 3위 | 일별 거래대금 랭킹 | 💰 거래대금 N위 |
| **신고가** | 52주 고가 근접 | `price ≥ wk52_high × 0.98` (2% 이내) | 스냅샷 `wk52_high` | 🏔️ 52주 신고가 N%↓ |
| **수급** (연속/전환) | 외국인·기관 연속 순매수 또는 순매수 전환 | 연속 ≥ 3거래일, 또는 전일 순매도→당일 순매수 | 일별 투자자별 순매수 히스토리 | 🏛️ 기관 N일 연속 / 순매수 전환, 🌏 외국인 순매수 |

**임계값 상수 (한 곳에서 관리)**

```
COUNTER_TREND_OUTPERF = 3.0   # %p, 역행 최소 아웃퍼폼
VOL_SURGE_MIN         = 1.5   # 거래량 급증 배수 (기존 surgeBadge와 동일)
VOL_SURGE_STRONG      = 2.5   # 강한 급증 (해석 문구 강화)
CAPITULATION_DROP     = -3.0  # %, 투매 최소 낙폭
TURNOVER_TOP_N        = 3     # 거래대금 쏠림 순위 컷
NEAR_HIGH_RATIO       = 0.98  # 52주 신고가 근접 (기존 nearHighBadge와 동일)
SUPPLY_STREAK_MIN     = 3     # 연속 순매수 최소 거래일
```

> `VOL_SURGE_MIN 1.5`·`NEAR_HIGH_RATIO 0.98`은 기존 `web/stocks/index.html`의 `surgeBadge`·`nearHighBadge`와 동일 임계라 일관성이 유지된다.

### 선별·우선순위

1. **후보 풀** — 추적 유니버스 전 종목.
2. **신호 수집** — 각 종목에 걸린 축을 모두 수집. 1개 이상이면 후보.
3. **종목당 1행** — 여러 축이 걸리면 뱃지를 묶어 한 행으로 표시(중복 금지).
4. **정렬 = 신호 강도 점수 내림차순.** 동점 시 거래대금 큰 순.

   ```
   score = 역행(아웃퍼폼 %p) ×2.0
         + 신고가(가까울수록) ×1.5
         + 투매(낙폭 × 급증배수) ×1.0
         + 수급(연속일수) ×1.0
         + 거래대금(역순위 가산) ×0.8
   ```

   가중치는 "역행·신고가 = 능동 신호 우대, 거래대금 = 보조"라는 원칙에서 출발한다. 운영하며 조정.
5. **표시 행 수 = 5~6행.**
6. **빈 상태** — 신호 0개(드묾)면 거래량 톱 5행으로 폴백하고 헤더에 "특이 신호 없음 · 거래량 순"을 표기한다.

### 한 줄 해석 — 규칙 기반 템플릿

축 조합별 결정론적 템플릿. `{}`는 실측값 치환. LLM 생성 안 함.

| 주신호 | 템플릿 |
| --- | --- |
| 역행 | `시장이 {kospi_pct}% {하락/상승}하는 동안 {stock_pct} {상승/선방}. {주체} {순매수/순매도}가 {함께 들어왔어요/우위였어요}.` |
| 투매 | `거래량이 평소의 {surge}배로 늘며 {stock_pct} 급락. {주체} 매도가 우위였어요.` |
| 신고가 | `{하락장에도/상승 흐름 속} 52주 신고가 {gap}% 이내. {주체}이 {streak}거래일 연속 사들이고 있어요.` |
| 거래대금 | `거래대금 코스피 {rank}위. 시총 비중이 커 지수 {방향}에 가장 큰 영향을 줬어요.` |
| 수급 전환 | `거래량 {surge}배 {증가} 속 {하락/상승}했지만, {주체}는 순매수로 돌아섰어요.` |

- `surge ≥ VOL_SURGE_STRONG`이면 "급증"→"폭증" 등 강도 문구만 교체(템플릿 구조는 동일).
- 수급 주체 우선순위: 외국인 > 기관 > 개인(한국 투자자 관점은 [SERVICE_RULES 라이브 스코어보드](../../SERVICE_RULES.md) 순서와 별개로, 신호 강도는 외국인 우선).

## B. ETF로 읽는 시황

### 헤드라인 분기 규칙

ETF 거래량·등락 랭킹으로 한 줄 시황을 결정한다.

| 조건 | 헤드라인 |
| --- | --- |
| 인버스 ETF 거래량 상위(≤2위) AND 코스피 하락 | `인버스 거래량 급증 · 하락 대비 수요 확대` |
| 레버리지 ETF 거래량 상위(≤2위) AND 코스피 상승 | `레버리지 거래량 급증 · 상승 베팅 확대` |
| 위 조건 모두 불충족 | `ETF 거래량 상위: {top1_name}` (중립 서술) |

### 근거 3종 선택

대표 카테고리별 1개씩, 데이터가 있으면 표시(없으면 생략).

1. **방향 베팅** — 인버스 또는 레버리지 중 거래량 상위 1개.
2. **반대 베팅 청산** — 레버리지/곱버스의 큰 낙폭 1개.
3. **안전자산** — 골드·채권 ETF 중 상승 1개.

### 톤 규칙 (중립 강제)

단정·감정 표현 금지. 서술형으로 누그러뜨린다.

| 금지 | 대체 |
| --- | --- |
| 패닉 국면 / 공포 | 하락 대비 수요 확대 |
| 폭발 / 투매 | 급증 / 매도 우위 |
| 대규모 손절 | 지수 낙폭의 N배로 조정 |
| ~에 베팅하고 있어요 | ~에 대비하거나 베팅하는 수요가 늘었어요 |

## 데이터 파이프라인 (실배선 시)

| 신호 필요 데이터 | 소스 후보 |
| --- | --- |
| 종목 등락률·거래량 | 기존 홈 랭킹 데이터(스냅샷 + 장중 갱신) |
| 거래량 20일 평균 (`vol_avg20`) | 스냅샷 (이미 존재, `surgeBadge`에서 사용 중) |
| 52주 고가 (`wk52_high`) | 스냅샷 (이미 존재, `nearHighBadge`에서 사용 중) |
| 투자자별 순매수·연속일 | 일별 투자자 데이터 — `data/supply_history.json` 또는 마감 수집(`fetch_closing_kospi.py`의 `investor_trading`) 확장 |
| 거래대금 랭킹 | 네이버/토스 거래대금 정렬 (신규 수집 필요 가능) |
| 코스피 등락률 | `/api/kospi-live` (기존) |
| ETF 거래량·등락 랭킹 | 기존 ETF 랭킹 데이터 |

미확보 항목: **연속 순매수 일수**·**거래대금 랭킹**은 현재 파이프라인에 없을 수 있어 실배선 전 소스 확정이 필요하다. 둘 다 못 구하면 해당 축은 표시하지 않는다(역행·거래량·신고가만으로도 동작).
