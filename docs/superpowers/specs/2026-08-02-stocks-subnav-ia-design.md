# 종목 시그널 서브 네비게이션 — 설계

작성일 2026-08-02 · 대상 `/stocks/` 정보구조

## 배경

StockRipple 벤치마크(`docs/analysis/2026-08-02-stockripple-benchmark.html`)에서 도입하기로 한 기능이 4개다.

1. 실적발표 캘린더
2. 테마 타임라인
3. 밤사이 브리지 · 국장 선반영 %p
4. 검증 근거 노출

이 중 1·2는 **새 표면이 필요한데 지금 구조에는 그것을 매달 자리가 없다.** 현재 상태를 조사한 결과는 이렇다.

- `/`는 301로 `/stocks/`에 리다이렉트된다 — 종목 시그널이 사실상 홈이다.
- GNB 1depth는 `브리핑 | 월배당` 2칸뿐이고, 정작 시그널은 메뉴에 없다(로고 클릭으로만 도달).
- `/stocks/`는 단일 파일 SPA이고 하위 화면 7개(`signals-all`·`sector`·`etf-rank`·`passive`·`ranking`·`etf-detail`·`income`)가 **인페이지 "더보기 →" 링크로만** 도달 가능하다. 해시(`#signals-all`) 라우팅이라 공유·검색 노출이 안 된다.
- 사이트맵에 등록된 비브리핑 페이지는 4개뿐이다.

기능을 붙이기 전에 자리를 먼저 만든다. **이 문서는 그 자리를 만드는 작업 하나만 다룬다.** 4개 기능은 각자 별도 스펙·계획을 갖는다.

## 확정된 정보구조

### 1depth — GNB (변경 없음)

```
Double-Shot   |   브리핑   월배당
```

캘린더·테마를 최상위로 올리지 않는다. 아직 만들지 않은 기능이 메뉴에 먼저 자리를 차지하는 것을 피한다.

### 2depth — 시그널 서브탭 (신설)

| 탭 | 연결 | 성격 |
| --- | --- | --- |
| 전체 | `/stocks/` | 기존 홈. 모든 영역의 요약이 모인 모듬 화면 |
| 특이신호 | `/stocks/#signals-all` | 기존 해시 화면 |
| 테마 | `/themes/` | **신규 실 페이지** (테마 타임라인 작업에서 신설) |
| 섹터 | `/stocks/#sector` | 기존 해시 화면 |
| ETF | `/stocks/#etf-rank` | 기존 해시 화면 |
| 일정 | `/calendar/` | **신규 실 페이지** (실적 캘린더 작업에서 신설) |

라벨은 **"특이신호"** 로 붙여 쓴다(홈 블록 제목 "오늘의 특이 신호"와 별개로, 탭은 짧게).

**탭에 넣지 않는 것** — 패시브 민감주·순위·ETF 상세는 지금처럼 인페이지 "전체 보기 →" 링크로 유지한다. 탭이 넘치는 것을 막고, 기존 진입 경로를 깨지 않는다.

### 홈과 탭의 관계

홈("전체" 탭)은 모듬이고 탭은 각 영역의 입구다. **탭이 있는 영역은 홈에도 대응하는 요약 블록이 있어야 한다** — 이 규칙이 "홈 = 모듬"이라는 약속을 지킨다.

조사 결과 기존 4개 탭은 이미 대응 블록과 "전체 보기 →" 링크를 갖고 있어 그대로 성립한다. 신설이 필요한 요약 블록은 2개이고, 각각 해당 기능 작업에서 만든다.

```
브리핑 스트립 → 밤사이 미국 반도체 시황 → 코스피 주도주 → 섹터별 대표 종목
  → 이번 주 자금 지도 → 오늘의 특이 신호 → 패시브 민감주
  → 진행 중 테마(신설) → 이번 주 일정(신설, 맨 아래)
```

블록 끝의 "전체 보기 →" 링크와 상단 탭은 **둘 다 유지한다.** 링크는 보고 있는 것을 이어보는 맥락 이동이고, 탭은 홈을 거치지 않는 상시 이동이라 역할이 다르다.

### 배치

탭 바는 **페이지 머리말 영역의 맨 아래**에 놓는다. `/stocks/` 기준으로는 검색창과 장상태·코스피·수급 패널 **아래**, 콘텐츠 블록 **위**다.

```
GNB
종목 시그널 BETA / 코스피 주도주 실시간 대시보드
검색창
장 상태 · 코스피 · 수급              ← 어느 탭에서든 참인 시장 맥락
─────────────────────────────────    ← 탭 바 (여기)
콘텐츠 블록                            ← 탭에 따라 바뀌는 영역
```

코스피·수급은 탭과 무관하게 참인 공통 맥락이라 탭 위에 둔다. 탭을 그 위에 놓으면 탭을 옮길 때마다 시장 수치가 사라지는 셈이 되어 어색하다.

`/themes/`·`/calendar/`에는 이 시장 패널을 복제하지 않는다. 실시간 폴링이 걸린 홈 전용 위젯이라 옮기는 비용이 크고, 그 페이지의 주제와도 직접 관계가 없다. 규칙은 **"각 페이지의 머리말이 끝나는 자리"** 로 통일한다 — `/stocks/`에서는 시장 패널 아래, 신규 두 페이지에서는 페이지 제목 아래가 그 자리다. 탭 바의 화면상 y좌표는 페이지마다 다르지만 "머리말 다음"이라는 의미 위치는 같다.

**구현 시 드러난 전제 오류 (2026-08-04, Task 1에서 수정).** 이 문서는 위 배치가 이미 성립해 있는 것처럼 썼지만, 실제로는 히어로·검색창·장상태·코스피·수급 패널이 전부 `#home`(`.screen` 중 하나)  **안에** 있었다 — `go('sector')`를 부르면 `#home`이 꺼지면서 이 전부가 함께 사라지는 구조였다. "코스피·수급은 어느 탭에서든 참인 공통 맥락"이라는 근거 자체가 성립하지 않았던 것이다. 구현 Task 1에서 이 블록을 `.screen` 밖(페이지 레벨, `.wrap`의 직계)으로 옮긴 뒤에야 이 배치 문단이 사실이 됐다. 문서가 코드보다 오래 사는 상황을 만들지 않기 위해 기록한다(SERVICE_RULES §10).

### 시각 규격 — ncai-design-system Tabs 준거

스타일은 **언더라인 탭**이다. 알약 탭 대비 6개가 들어가도 시각적으로 가볍고, 콘텐츠를 가르는 경계로 읽혀 조용하다. 이는 취향이 아니라 [ncai-design-system](https://github.com/GronkOut/ncai-design-system)의 규정이다 — Tabs는 **Underline 변형을 기본**으로 한다.

조사 결과 **Double-Shot은 이미 이 시스템의 토큰을 쓰고 있다.** 변수명만 줄여 놓았을 뿐 값이 일치한다.

| ncai | Double-Shot | 값 |
| --- | --- | --- |
| `--color-canvas` | `--canvas` | `#ffffff` |
| `--color-surface-soft` | `--surface-soft` | `#f9fafb` |
| `--color-surface-inset` | `--surface-inset` | `#eef1f5` |
| `--color-hairline` | `--hairline` | `#e5e7eb` |
| `--color-ink` | `--ink` | `#13151a` |
| `--color-primary` | `--primary` | `#006eff` (다크 `#1c82ff`) |

따라서 새 토큰을 도입할 필요가 없다. 시스템이 React + Base UI(`@ncai/design-system` + `@base-ui/react`) 전제인데 Double-Shot은 빌드 없는 정적 HTML이므로, **컴포넌트는 가져오지 않고 토큰·규칙만 따른다.**

탭 규격은 다음과 같다.

| 항목 | 값 |
| --- | --- |
| List | 하단 1px `--hairline` 디바이더, flex 좌측 정렬, gap 없음 |
| Tab 크기 | `min-height: 40px`, 좌우 패딩 16px |
| Tab 타이포 | `.label-14m` — 14px / weight 500 / line-height 1.2 / letter-spacing −0.16px |
| 기본 색 | `--body-muted` |
| Hover | 텍스트 `--ink` |
| **Active** | **텍스트·언더라인 모두 `--primary`.** 언더라인은 2px, `margin-bottom: -1px`로 List 디바이더 위에 겹친다 |
| Focus | 언더라인 색 유지 + dotted outline 1px (전역 정책의 예외) |

**weight는 500으로 고정한다 — 활성 탭을 굵게 만들지 않는다.** 시스템의 명시적 금지 사항이며(굵기 변화는 레이아웃 점프를 만든다), 활성 신호는 primary 컬러 하나로 통일한다. 초기 목업이 활성 탭을 `ink` + 굵게로 그렸는데 그건 규격 위반이었다.

## 컴포넌트 설계

### 왜 공용 스크립트인가

탭 바는 최종적으로 세 곳(`/stocks/`·`/themes/`·`/calendar/`)에 똑같이 떠야 한다. 그런데 `/stocks/index.html`은 손으로 쓴 정적 HTML이고 신규 두 페이지는 `generate_html.py`가 만든다. **마크업을 양쪽에 복사하면 §30에서 겪은 "같은 로직 이중 구현" 사고가 그대로 재현된다** — 한쪽만 고쳐지고 다른 쪽이 방치돼도 겉보기엔 둘 다 정상으로 보인다.

그래서 각 페이지에는 빈 껍데기만 두고 탭 정의를 한 곳에만 둔다. 탭을 켜고 끄는 것도 그 파일 한 곳만 바꾸면 세 페이지에 동시에 반영된다.

`stocks-home.js`는 이미 3,160줄·206KB라 여기에 넣지 않는다. 독립 파일이 작고 경계가 분명하며, `/themes/`·`/calendar/`가 거대한 홈 스크립트를 통째로 로드할 이유도 없다.

### 인터페이스

**각 페이지가 두는 것**

```html
<nav id="ds-subnav" aria-label="종목 시그널 메뉴"></nav>
```

**`ds-subnav.js`가 노출하는 것**

| 이름 | 용도 |
| --- | --- |
| `window.dsSubnavSync()` | 현재 탭 강조를 다시 계산해 반영. SPA 화면 전환 후 호출 |
| `window.__dsSubnav` | 테스트용. `{ TABS, resolveActiveTab }` |

`stocks-home.js`의 `go()` 마지막에 한 줄만 추가한다. 프로젝트가 이미 쓰는 옵셔널 호출 관례(`if (typeof initX === 'function')`)를 따라 결합을 최소로 둔다.

```js
if (typeof window.dsSubnavSync === 'function') window.dsSubnavSync();
```

### 탭 정의

```js
const TABS = [
  { id: 'home',    label: '전체',     href: '/stocks/',              screen: 'home' },
  { id: 'signals', label: '특이신호', href: '/stocks/#signals-all',  screen: 'signals-all' },
  // { id: 'themes',   label: '테마', href: '/themes/' },              // 테마 타임라인 완성 시 점등
  { id: 'sector',  label: '섹터',     href: '/stocks/#sector',       screen: 'sector' },
  { id: 'etf',     label: 'ETF',      href: '/stocks/#etf-rank',     screen: 'etf-rank' },
  // { id: 'calendar', label: '일정', href: '/calendar/' },            // 실적 캘린더 완성 시 점등
];
```

`screen`이 있으면 `/stocks/` 내부 화면이고, 없으면 독립 페이지다. 이 한 필드가 아래 클릭 동작을 가른다.

### 현재 탭 판정 — `resolveActiveTab(pathname, hash)`

순수 함수로 분리한다. DOM·전역 상태를 안 읽으므로 테스트가 쉽다.

| 입력 | 결과 |
| --- | --- |
| `/themes/...` | `themes` |
| `/calendar/...` | `calendar` |
| `/stocks/` + `#signals-all` | `signals` |
| `/stocks/` + `#sector` | `sector` |
| `/stocks/` + `#etf-rank` | `etf` |
| `/stocks/` + 해시 없음 또는 `#home` | `home` |
| `/stocks/` + 그 외 해시(`#passive`·`#ranking`·`#mom-track` 등) | `home` |
| `/stocks/005930/` 등 그 외 경로 | `null` (아무 탭도 활성 아님) |

정의에 없는 탭 id로 해석되면 `null`을 반환한다 — 아직 점등하지 않은 테마·일정 경로에 어떤 이유로 진입해도 깨지지 않는다.

`#passive`처럼 탭이 없는 화면에서는 "전체"를 활성으로 둔다. 아무 탭도 활성이 아닌 것보다, 사용자가 시그널 영역 안에 있다는 사실을 유지하는 쪽이 방향 감각에 낫다.

### 클릭 동작

`go()`가 `history.pushState`로 해시를 바꾸는데 **pushState는 `hashchange`를 발생시키지 않는다.** 그래서 링크 기본 동작에만 맡기면 화면 전환과 탭 강조가 어긋난다. 클릭을 가로챈다.

```
탭 클릭
 ├ 대상에 screen이 있고 && 현재 경로가 /stocks/ && window.go가 함수
 │    → preventDefault, go(screen) 호출, 강조 갱신
 └ 그 외 (독립 페이지이거나, go가 없는 페이지)
      → 기본 링크 이동
```

`window.go`가 없으면 가로채지 않으므로, `/themes/`에서 "섹터" 탭을 누르면 `/stocks/#sector`로 정상 이동한 뒤 그 페이지의 해시 복원 로직이 화면을 띄운다.

### 갱신 시점

- 최초 로드 (`DOMContentLoaded`)
- `hashchange` — 주소창 직접 수정·외부 앵커 링크
- `popstate` — 뒤로/앞으로 가기
- `dsSubnavSync()` — `go()` 호출 후

## 저하 동작과 에러 처리

이 컴포넌트는 **없어도 기존 기능이 전부 동작해야 한다.** 홈 블록의 "전체 보기 →" 링크가 그대로 살아 있으므로 탭 바는 부가 경로다.

- `#ds-subnav` 껍데기가 없는 페이지에서 스크립트가 로드되면 조용히 아무것도 안 한다. `main.js`가 쓰는 `if (!el) return` 가드 관례와 같다.
- `resolveActiveTab`이 `null`을 주면 아무 탭도 강조하지 않고 탭 바 자체는 그대로 보인다.
- CSS는 **모든 변수에 폴백을 둔다** — `var(--hair, #E5E7EB)` 형태. §5에서 CSS 변수 하나가 없어 랜딩이 통째로 빈 화면이 된 사고가 있었다. 세 페이지가 서로 다른 스타일시트(`stocks-home.css` / `style.css`)를 쓰고 변수명도 갈려 있으므로(`--hair` vs `--hairline`), 값이 없을 수 있다고 전제하고 위 표의 ncai 값을 폴백으로 박는다.
- 스크립트 로드는 `defer`. 렌더를 막지 않는다.

`main.test.mjs`·`stocks-home.test.mjs`가 쓰는 방식을 따른다 — **순수 함수를 별 파일로 복제하지 않고**, node:vm 샌드박스에서 실제 프로덕션 파일을 최소 DOM 스텁과 함께 실행한 뒤 `window.__dsSubnav`로 꺼내 검증한다. 사본이 원본과 어긋나는 것(§20류 사고)을 막기 위한 기존 관례다.

검증 항목.

1. 경로·해시 조합별 활성 탭 판정 — "현재 탭 판정" 표의 8케이스 전부.
2. 정의에 없는 해시(`#passive`)가 `home`으로 떨어지는지.
3. 종목 상세 경로에서 `null`인지.
4. 아직 점등하지 않은 탭(테마·일정) 경로에서 깨지지 않는지.
5. `TABS`의 `screen` 값이 실제 존재하는 화면 id와 일치하는지 — `web/stocks/index.html`을 읽어 `class="screen"` id 목록(과 `id="home"`)을 뽑고 대조한다. 오타로 죽은 탭이 나가는 것을 막는다. `screen`이 없는 탭(테마·일정 같은 독립 페이지)은 이 검사에서 제외한다.
6. `href`가 `screen`과 어긋나지 않는지 — `screen`이 있는 탭은 `href`의 해시가 `#{screen}`이거나(내부 화면), 해시가 없으면 `screen`이 `home`이어야 한다. 정의를 손으로 고치다 둘이 갈라지는 것을 막는다.

DOM 이동·시각 결과는 스텁 환경에서 확인할 수 없어 브라우저에서 별도 확인한다(기존 테스트 파일에 같은 단서가 달려 있다).

## 미확정 — 후속 판단

**탭 바 스티키 고정.** 언더라인 탭은 스티키로 만들기 쉽지만 이번엔 넣지 않는다. `stocks-home.css:296`의 `.sbx-tabs`(섹터별 대표 종목 탭)가 이미 `position:sticky; top:52px`으로 GNB 바로 아래에 붙는데, 서브탭을 같은 위치에 고정하면 둘이 겹친다. 해소하려면 `.sbx-tabs`의 `top`을 서브탭 높이만큼 밀어야 하고 그건 별개의 시각 변경이다. 탭 바를 먼저 넣어 실제로 스크롤해 보고 판단한다.

**종목 상세 페이지 탭 노출.** 45개 페이지가 `generate_html.py` 산출물이라 범위가 커진다. 탭 체계가 자리 잡은 뒤 재검토한다.

## 후속 작업과의 연결

이 작업이 끝나면 나머지가 다음 순서로 붙는다. 각각 별도 스펙을 쓴다.

| 순서 | 기능 | 이 작업과의 접점 |
| --- | --- | --- |
| 1 | 실적발표 캘린더 | `/calendar/` 신설 + `TABS`의 일정 주석 해제 + 홈 맨 아래 "이번 주 일정" 블록 |
| 2 | 밤사이 브리지 · 선반영 %p | "전체" 탭(홈)에 **신규 블록**. 07:30~09:00에만 노출 |
| 3 | 검증 근거 노출 | 접점 없음. 브리핑 수치 옆에 붙는다 |
| 4 | 테마 타임라인 | `/themes/` 신설 + `TABS`의 테마 주석 해제 + 홈 "진행 중 테마" 블록 |

캘린더를 먼저 두는 이유는 §19·§23·§29 시제 사고 재발 방지가 걸려 있어서다. 다만 그 작업의 본체는 화면이 아니라 `data/earnings_calendar.json`과 브리핑 시제 주입이고, `/calendar/` 화면은 같은 데이터를 쓰는 부산물이다.
