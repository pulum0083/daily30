# 배당 인컴 설계기 — 설계

> stock-page-engine 하위 기능. 홈 3번째 렌즈(인컴). 월배당·커버드콜 투자자를 위한
> "목표 인컴 → ETF 조합 + 정직한 분배 품질 + 종합과세" 통합 도구.

## 1. 문제와 차별점

한국 리테일의 월배당·커버드콜 붐(2024~2026)은 진짜고, "월배당 ETF 조합 / 커버드콜
원금 / 금융소득종합과세 ETF"는 **아직 아무도 제대로 안 잡은 검색어**다.

**경쟁력은 기능 수가 아니라 "정직 레이어"에 있다.** 커버드콜 ETF의 함정은 분배율이
총수익이 아니라는 것이다. 고분배 상당수가 원금을 분배금으로 돌려주고(원금성 분배)
가격이 녹는다. 운용사·판매사 누구도 이걸 보여주기 싫어한다. 더블샷의 톤(실측만,
과장 금지, 면책 규율)과 정확히 같은 목소리로 이걸 까는 게 차별점이다.

**실증(2026-06-13):** TIGER 미국30년국채커버드콜 — 분배율 TTM 13.02%인데 총수익
Y1은 1.85%. 가격이 약 −11% 빠졌다는 뜻. "13% 받는 줄 알았는데 실제론 1.85% 벌었다."

## 2. 핵심 지표

```
가격침식 프록시 = 총수익률(Y1) − 분배율(TTM)
   ≥ 0          : 가격 유지·상승하며 분배 → 건전
   −분배율/2 ~ 0 : 주의
   < −분배율/2   : 원금성 분배 (고분배율인데 가격 급락) → 경고
```

> 명시적 ROC(원금분배) 분해 데이터는 네이버에 없다. 위 프록시가 대체한다.
> 총수익·NAV성과 모두 분배금 재투자 기준이라, 가격만의 변화는 총수익−분배율로 추정.

## 3. 데이터 소스 (전부 네이버 etfAnalysis, 무인증 — 2026-06-13 검증 완료)

`m.stock.naver.com/api/stock/{code}/etfAnalysis` 한 방에 다 들어있다.

| 필드 | 용도 |
| --- | --- |
| `marketValue` | AUM — 1조+ 필터 |
| `dividend.dividendYieldTtm` | TTM 분배율 |
| `dividend.dividendPerShareTtm` | 주당 분배금(TTM) |
| `dividend.dividendMonthThisYear` | 분배 지급 월("1,2,3,4,5") — **인컴 평탄화** |
| `dividend.dividendCountThisYear` | 연 분배 횟수 |
| `returnPerformanceList` | 기간별 총수익(D1/W1/M1/M3/M6/YTD/Y1) |
| `navPerformanceList` | 기간별 NAV 성과 |
| `taxationTypeCode` | 1=국내주식형 / 2=배당과세형(채권·커버드콜·기타) / 4=해외주식형 |
| `totalFee` | 총보수 |
| `listedDate` | 상장일 — 1년 미만이면 분배율 TTM 신뢰 낮음 경고 |

**못 구하는 것 (정직하게):**
- 명시적 원금분배(ROC) 분해 → 가격침식 프록시로 대체.
- 분배금 per-payment 시계열(날짜·금액) → 네이버 `dividend` 엔드포인트 404. 세이브로/
  운용사 필요. **v1엔 불필요** — 분배 월 + TTM으로 forward 인컴 추정 충분.

## 4. UI 구조 (2026-06-13 피벗 확정)

**히어로 = 랭킹(SEO), 서포트 = 단발 시뮬레이터.** "보유 종목 저장형 트래커"는 접는다.
이유 — 카테고리 과밀(Snowball/Sharesight/증권사앱), 입력 마찰 + 정적 서빙(로그인 없음)에
저장 불가, 인터랙션 뒤 도구라 SEO 검색 루프 기여 0(닫힌 루프 회귀). 자세히는 CONTEXT-NOTES 결정 4.

1. **히어로 — 인컴 ETF 랭킹**: AUM 1조+ 배당·커버드콜 ETF. 분배율 TTM · 총수익(1y) ·
   **가격침식 프록시** · **건전성 뱃지(건전/주의/원금성)**. 정렬 토글(분배율/건전성/총수익).
   명명된 콘텐츠 "월배당·커버드콜 건전성"으로 롱테일 검색어 선점.
2. **서포트 — 인컴 시뮬레이터(단발, 저장 안 함)**: 보유 종목(KR + 해외 직상장) + 금액 입력 →
   ① 현재 연/월 인컴 ② **내 보유 중 원금성 종목 콕 집어 경고**(해자가 "내 돈" 얘기가 됨)
   ③ 내 숫자로 종합과세 노출 ④ 목표까지 갭 + 건전 ETF로 메우기 제안(→ 랭킹으로 환류).

**유니버스 필터**: 이름 패턴(배당/커버드콜/프리미엄/리츠/인컴) + `dividendYieldTtm > 0` +
AUM 1조+. (정확한 패턴은 실행 분포로 확정)

## 6. 규칙 준수

- **SERVICE_RULES 0번(실측만)**: 분배율·총수익·AUM은 네이버 실측. 프록시는 실측값의
  산술 파생(LLM 생성 아님). 위반 아님.
- **YMYL·면책**: 세금 계산은 "예상치, 개별 상황 다름" 면책 필수. 투자 권유 아님 명시.

## 7. 범위 절단

- **v1**: 유니버스 + 카드(건전성 뱃지) + 인컴 목표 조합 + 종합과세 경고.
- **v2**: 분배금 per-payment 시계열(세이브로/운용사) → 정확한 월별 인컴 캘린더.
- **안 함**: 명시적 ROC 분해(데이터 부재), 개별 종목 배당주(ETF만), 실시간 분배 예측.

## 8. 오픈 이슈

1. 유니버스 이름 패턴 — 실행 분포로 확정 필요(false positive 점검).
2. 가격침식 프록시 임계(−분배율/2) — day-1 분포 보고 조정.
3. 종합과세 계산 깊이 — v1은 "2천만원 임계 경고"까지, 누진세율 정밀 계산은 추후.
