# 종목 상세 페이지 재설계 + 칩보드 분리 설계

/ `web/stocks/{code}/` 상세 페이지를 AI 브리핑 연결 중심으로 재설계하고, 칩보드 외부 의존을 끊어 100% 인하우스 데이터로 전환한다.

작성일: 2026-06-27
검증: `web/stocks/005930-proto/index.html` (삼성전자 실데이터 프로토타입, 미리보기 완료)

## 배경 · 목적

`/stocks/{code}/` 영구 페이지는 검색 유입을 복리로 쌓는 트래픽 자산이다([[project_etfnow_strategy]]). 현재 페이지는 시세·이동평균·52주·외국인보유율(인하우스 실측) + 목표주가·수급·영업이익(외부 칩보드)으로 구성된다.

**문제.** 데이터 완성도로는 네이버·토스를 못 이긴다. "정보를 더 넣는" 방향은 지는 게임이다.

**전략.** 더블샷만의 무기는 정보량이 아니라 **"AI 브리핑과 연결된 맥락"**이다. 다른 어디에도 없는 것 — 이 종목이 브리핑에서 픽이었나·맞았나, 오늘 어떤 신호에 잡혔나, 더블샷 예측 적중률. 여기에 "실측만 보여주는 정직함"을 더한다.

**페이지 역할 (우선순위).**
1. 검색 유입 랜딩 → 브리핑 구독 전환.
2. 종목 판단 의사결정 도구.
3. (브리핑 독자 심화 — 링크 연결만으로 충족, 별도 설계 불필요.)

## 핵심 원칙 — 데이터 게이팅 (종목 게이팅 아님)

"큰 종목만 풍성하게"가 아니라 **"데이터 있는 섹션은 보여주고, 없으면 통째로 숨긴다"**. 수동 큐레이션 리스트를 만들지 않는다. 각 섹션이 데이터 유무로 자동 노출/숨김된다.

실측으로 따진 41 유니버스 커버리지.

| 단계 | 보유 섹션 | 종목 수 |
| --- | --- | --- |
| 풀버전 | 시그널 + 트랙레코드 + 적중률 + 실측지표 + 목표주가 + 영업이익 | 2 (삼성·하이닉스) |
| 중간 | 시그널 + 트랙레코드 + 적중률 + 실측지표 (+ 네이버 목표가·영업이익 있으면) | ~10 (픽 보유) |
| 얇은버전 | 시그널 + 적중률 + 실측지표 | ~29 (픽 0·칩보드 0) |

> 얇은버전(71%)이 전략의 급소다. 트랙레코드(픽 12종목)·칩보드(2종목)가 없으면 종목-고유 차별 콘텐츠가 사라진다. 이를 **오늘의 시그널(C)**로 보강한다 — `/api/signals`는 픽보다 훨씬 많은 종목을 매일 커버한다. 그리고 브리핑이 쌓이면 트랙레코드가 두꺼워지는 복리 구조다.

## 섹션별 설계

### A. 더블샷 AI 픽 트랙레코드 (빌드 타임)

이 종목이 브리핑에서 픽됐던 이력 + 픽 이후 실측 채점.

- **채굴.** `web/briefings/*/*/analysis_snapshot.json`(현재 35개)을 종목코드로 스캔. 한국 픽은 6자리 코드라 페이지와 1:1 매칭. 각 픽의 날짜·브리핑타입·신호·시나리오태그·진입·목표·손절 추출.
- **채점 (실측·종가 기준).**
  - 평가 구간 — 픽 다음 거래일부터 **픽 후 15거래일**과 현재 중 빠른 쪽까지. (무한정이면 "거의 다 도달"로 부풀려져 부정직.)
  - 판정 — 일봉 종가 순회, 먼저 닿는 것 채택. 손절가 이하 먼저 → **손절** · 손절 전 목표가 이상 → **목표 도달**(며칠 만에) · 둘 다 미터치 → **진행 중**.
  - 표시 수치 — 진입가 대비 ① 구간 내 최대 종가 수익률, ② 현재가 수익률. 토스→네이버 폴백(`validate_analysis._fetch_kospi_realdata`/`_fetch_us_realdata` 재사용).
- **표시.** 요약("N번 픽 · 목표 도달 X · 진행 중 Y") + 픽별 행(날짜·타입칩·신호·진입→목표·결과배지·수익률). **틀린 픽도 그대로 노출** — 정직함이 신뢰를 만든다. 각 행에 원본 브리핑 링크.
- 픽 0종목은 섹션 자동 숨김.

### B. 더블샷 브리핑 적중률 (사이드바, 빌드 타임)

- `data/briefings.json`(103건)에서 코스피·미국 방향 예측 적중률 집계.
- 구독 CTA(`/briefings`)로 역할 1(전환) 수행.
- 모든 페이지에 표시(종목 무관 신뢰 배지). 단 이것만으론 종목-고유 차별이 아니므로 C·A로 보강.

### C. 오늘의 시그널 (클라이언트 실시간)

- `/api/signals` 인하우스. `classifyStock`+`classifySupply`가 역행·52주 신고가·거래량 급증·외국인/기관 연속 순매수 등을 종목 단위로 분류 + `whyText` 한 줄 설명.
- **구현.** 페이지가 클라이언트에서 이 종목의 신호를 조회. 두 안 중 택1 — (a) `/api/signals?code=XXX` 단일 종목 조회 엔드포인트 추가, (b) `/data/stocks-snapshot.json` fetch 후 `_signals-core`의 분류 로직을 클라이언트에서 재실행. **권장 (a)** — 분류 로직 중복을 피하고 수급 신호까지 일관 처리.
- **갱신 기준.** 장중 실시간, 마감 후 확정. `/api/signals`의 `asOf`(isToday/label)·phase 사용.
- **세션 날짜 적응 타이틀.** 데이터가 오늘이면 "오늘의 시그널 · 오늘 장 기준", 과거 세션이면 "6/25(목) 시그널 · 6/25(목) 장 마감 기준". 휴장일·다음 날에도 깨지지 않음.
- 신호 0개면 섹션 숨김.

### 헤더 스파크라인 + 툴팁

- 20일 종가 스파크라인. 라벨 "최근 20거래일 종가" (타이틀과 좌측 18px 열 정렬).
- 곡선 마우스 오버 → 그래프 위에 "날짜 · 종가" 툴팁(마우스 추적). `#hero-stock`을 `position:relative`로 기준 삼음.
- `data-dates`로 날짜 매핑.

### 실측 핵심 지표 (빌드 타임)

- **52주 범위** bar(현재가 위치 %), **이동평균** 20·200일선 대비 카드, **외국인 보유율** + 추세 스파크라인(`foreign_spark`), **해외 연동** 미 벨웨더(섹터 매핑 있을 때).
- 전 종목 실측(stocks-snapshot). 색상은 사이트 규칙(상승=빨강 `--up`/하락=파랑 `--dn`).

### 증권사 목표주가 · 분기 영업이익 (네이버 재소싱)

- 칩보드(`/chips/api/*`) 의존 제거. **네이버 금융에서 컨센서스 목표주가·분기 영업이익을 인하우스 수집** → `generate_html --stocks` 빌드 타임 주입.
- 목표주가 UI — 레인지 바(최저·평균·최고 + 현재가 마커) + 전체 표(증권사·목표가·의견·발표일·상승여력). 상승여력 색은 사이트 규칙.
- 영업이익 UI — `stocks.css`의 기존 `.fin-chart`/`.fin-col`/`.fin-bar` 구조 재사용(빨강 막대·베이스라인·범례).
- 데이터 없는 종목은 섹션 자동 숨김.

## 칩보드 분리 · 청소

상세 페이지는 위 설계로 칩보드와 **완전 독립**. 칩보드 종료 시 별도 청소 필요.

- **홈 "AI 반도체 칩보드" 위젯** (`loadChipWidget()` → `/chips/api/prices`) — `web/index.html`·`web/stocks/index.html`. 제거 또는 대체.
- **섹터 페이지 GNB "Chip-Board" 링크** (`/chips`) — 섹터 8개 + income-designer.
- **`vercel.json`의 `/chips` 라우트 2개** 제거.
- 이 청소는 상세 페이지 재설계와 **별개 작업**(같은 시점에 묶어 처리 가능).
