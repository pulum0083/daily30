# "왜 움직였나" — 라이브 곡선 + 뉴스 핀 설계

작성일: 2026-06-25 · 상태: 설계 확정, 구현 계획 대기

## 1. 배경 / 문제

종목 허브를 콘텐츠로 채웠으나(주도주·거래량/상승/하락 톱·픽 트래킹) "100% 만족스럽지 않다"는
피드백. 진단: 허브가 **숫자의 나열**이다. 장중에 사용자가 빨간/파란 숫자를 보며 떠올리는
첫 질문은 "왜? 무슨 일인데?"인데, 그 "왜"가 어디에도 없다. 다른 증권앱과 똑같은 랭킹 리스트.

"왜"야말로 우리 무기다 — AI 브리핑 reasons, 장중 이슈 브리핑, 픽 시나리오. 숫자에
**내러티브를 붙이는 레이어**가 차별점인데 허브에서 끊겨 있다.

불만족 위치(사용자 확인): **3번 = 움직임↔이유를 잇는 흐름**이 메인. 3번이 엔진이 되면
1번(허브)은 그 산출물로 채워지고, 2번(개별 종목)은 데이터 조합.

## 2. 컨셉

> 코스피 주도주 위젯에 **장중 곡선 + 뉴스 핀**을 흡수한다. 주도주를 탭하면 그 자리에서
> 인라인 확장되어, 백필된 오늘 곡선 위로 **실시간 시세가 쌓이고 뉴스가 그 시점에 찍힌다.**
> 사용자는 라이브 시세를 보다가 "아, 이 지점이 이래서 꺾인 거구나"를 이 서비스에서 안다.

- **홈(코스피 주도주)**: **주도주 카드 안에 통합.** 타일(삼성/하이닉스/현대차) 선택 → 그 아래
  선택 종목의 곡선+뉴스가 렌더(타일 선택 시 스왑). 별도 카드 아님 — 한 카드 안에 타일+곡선.
  - **기존 벨웨더(🇺🇸 짝 벨웨더 ●LIVE)·외국인 보유율 행(`.us-detail`)은 홈에서 제거**하고 그 자리를 곡선이 차지.
    제거가 아니라 **종목 상세 페이지로 이전** — 해당 종목의 미 벨웨더·외국인 보유율을 상세에서 보여준다.
- **종목 상세**: 같은 컴포넌트를 크게, 헤더 카드 아래 "오늘 장중" 카드로 기본 펼침.
- 엔진·데이터는 하나, 표면만 둘.
- 별도 "왜 움직였나" 섹션은 만들지 않는다(주도주 위젯에 단일화).

## 3. 핵심 원칙 — 정직성 (운영규칙 0번의 뉴스판)

기존 이슈 브리핑과 **동일한 2단계 안전 패턴**: RSS가 기사·pub_date를 보장하고, Gemini는
선별·요약·감성분류만. 날짜·헤드라인을 못 지어낸다.

**방향 일치 게이트 (코드로 강제):**

| 조건 | 등급 | 표시 |
| --- | --- | --- |
| 긍정 헤드라인 + 주가 상승 (또는 부정+하락) | `why` | 부드러운 인과 한 줄 ("~보도에 매수세 유입") |
| 감성↔방향 불일치, 또는 시장 전반 뉴스 | `related` | 병치만, "(인과 단정 안 함)" 명시 |
| 오늘 기사 0건 | `none` | "뚜렷한 뉴스 없음 · 수급/테마 추정" |

- LLM이 인과를 우겨도 코드 게이트가 `related`로 강등한다.
- 모든 줄에 **실제 출처 링크**. 사용자가 헤드라인으로 직접 검증.
- "왜"의 한 줄은 반드시 실제 헤드라인을 패러프레이즈 + 부드러운 연결어만. 숫자·사실 신규 생성 금지.

## 4. 아키텍처 — 파이프라인(브리핑 생성) 0줄 수정

| 영역 | 무엇 | 소스 / 비고 |
| --- | --- | --- |
| 엔진 (신규) | `scripts/fetch_movers_why.py` | vol-top `all`에서 무버 추림 → 종목명 RSS → Gemini 선별·요약·감성 → 방향 게이트 |
| 산출물 (신규) | `web/data/movers-why-{date}.json` (+ `movers-why-live.json`) | 종목별 events[] |
| 곡선 API (확장) | `api/intraday.mjs`에 `?code=` 분기 | `fetchMinutes(code)` — 네이버 fchart 1분봉 (기존 함수 재사용) |
| 라이브 누적 | 주도주 폴링에 점 append | 인메모리 + sessionStorage (스코어보드 스파크라인 패턴) |
| 렌더 (확장) | 홈 주도주 위젯 탭 확장 + 상세 "오늘 장중" 카드 | `web/stocks/index.html`, 종목 상세 템플릿, `web/assets/stocks.js` |

**스케줄**: GHA-native schedule(MARKET 슬롯 30분 cadence) 재사용. Vercel cron 미사용(규칙 10번).

### 산출물 형태 (종목 1건)

```json
{ "code":"005930","name":"삼성전자","changePct":5.9,"surge":2.3,
  "events":[
    {"time":"09:32","headline":"삼성전자, 엔비디아에 HBM4 공급 본격화","url":"https://...",
     "source":"한국경제","why":"HBM4 공급 확대 보도에 매수세 유입","tier":"why","sentiment":"pos"}
  ]}
```

## 5. 곡선 동작

- **백필**: 진입 시 `api/intraday?code=`로 09:00~현재 1분봉을 한 번에 깔아 곡선이 처음부터 꽉 참.
- **라이브 누적**: 폴링 시 새 점 append, 머리 점이 우측으로 이동.
- **뉴스 핀**: `events[]`의 pub_time을 09:00~15:30 x축에 매핑해 곡선 위에 꽂음. 번호로 아래 타임라인과 연결.
- 핀 색: `why`=빨강(채움), `related`/`none`=회색(테두리).

## 6. 엣지 케이스

- **비대상 종목 상세(뉴스 없음)**: 곡선만 깔끔하게. 핀은 뉴스 있을 때만, 없으면 "오늘 관련 뉴스 없음" 한 줄.
- **장 마감 후**: 그날 곡선+뉴스 종일 보존(아카이브), 다음 거래일 09:00 리셋.
- **휴장일 / 데이터 없음 / 픽 없음**: 섹션 깨지지 않고 숨김. 콘솔 에러 0.

## 7. 범위

- **1차**: 엔진(`fetch_movers_why.py`) + `intraday.mjs` 확장 + 홈 주도주 흡수 + 상세 곡선.
- **2차(미룸)**: 클릭 시 실시간 RSS 보강(C 단계), ETF·비주도주 종목 확대.

## 8. 검증 기준 (성공 정의)

1. 게이트 분류 정확 — 긍정+상승→`why`, 긍정+하락→`related` 강등 실제 동작.
2. 곡선이 실측 1분봉으로 백필되고 라이브로 누적된다.
3. 뉴스 0건 종목은 "수급/테마 추정"으로 정직 표기.
4. 휴장일·픽없음·데이터누락 시 깨짐 없이 숨김, 콘솔 에러 0.
5. 같은 종목이 주도주·곡선·핀에서 모순 없는 동일 수치.
