# 종목 페이지 엔진 — Context Notes

작업 중 내린 결정과 그 이유를 계속 덧붙인다. 플랜: [2026-06-22-stock-page-engine.md](2026-06-22-stock-page-engine.md)

## 배경

`/stocks/{code}/` 프로토 평가 결과, UI·정보설계는 서비스급이나 4개 HTML 파일이 인라인 복붙(공유 에셋 0, fetch 0, 날짜 하드코딩)이라 종목 확장이 불가능. 목표는 "검색 유입 복리 자산"이므로 손작성 → 생성기 전환이 변곡점.

## 확정 결정 (2026-06-22)

1. **생성 방식 = generate_html.py 확장.** 별도 스크립트 대신 기존 config-driven Jinja2 생성기를 재사용. 이유: 코드/패턴 중복 회피, 사이트맵·write 헬퍼·make_env 재사용.
2. **데이터 깊이 = 빌드 타임 실측 주입만.** 런타임 LIVE 폴링은 후속. 이유: 가장 빨리 "진짜 데이터 페이지"가 나오고 검증 부담이 작음.
3. **초기 범위 = 005930·000660·005380(3종).** 이유: 생성기 검증에 충분, 작게 시작. 005380은 현 인덱스가 `stock.html?code=`로 폴백하던 종목이라 클린 URL 일원화 검증도 겸함.

## 설계 판단

- **52주 범위는 별도 산출.** `_fetch_kospi_realdata()`가 52주를 안 주므로 토스 캔들(count=300≈1년)에서 min/max를 생성기 쪽 래퍼(`stock_realdata`)로 계산. `validate_analysis.py`는 검증 파이프라인 보호 위해 수정하지 않고 import만.
- **목표가·분기실적은 일러스트 유지.** 실측 소스(네이버 컨센서스·분기재무) 미연동 상태. SERVICE_RULES 0번(실측만 표시) 준수 위해 일러스트 배너로 정직 표기. 후속에서 네이버 연동 시 실측 전환.
- **수급 7일은 조건부.** `data/supply_history.json`에 종목 데이터 있을 때만 주입, 없으면 일러스트.
- **템플릿은 005930 프로토에서 추출.** 792줄 전체를 플랜에 재현하지 않고 변수 매핑표로 derivation 지시. 프로토가 소스 오브 트루스, 추출 후 생성기가 덮어씀.
- **인덱스 허브 전면 템플릿화는 범위 밖.** Task 6은 링크 정합성(클린 URL 일원화)만. 인덱스 랭킹 데이터 연동은 별도 과제.

## 실행 중 내린 추가 결정 / 발견

- **peer 모델 = {code,name} 객체**: 리뷰 지적으로 변경. peer는 표시용 참조라 레지스트리 등록 없이 이름 해결. 생성 범위 3종 유지.
- **52주 = 토스→네이버 폴백**: `_fetch_stock_closes`가 토스 전용이라 로컬(토스 미설정)에서 52주가 None→템플릿 "0" 표시(§0 위반)되던 버그 발견. `_naver_daily_closes` 폴백 추가 + 템플릿 `{% if rd.week52_low %}` 가드(없으면 "준비 중").
- **헤더 차트 단일화**: 프로토 템플릿이 실측 sparkline + 정적 기간차트(가짜 탭·하드코딩 고점/저점) 둘 다 렌더. 정적 차트·탭·하드코딩 콜아웃 제거, 실측 sparkline 하나로. 고점/저점은 sparkline(20일) min/max 실측값 "최근 고점/저점"으로 라벨(52주와 구분).
- **peer 링크 graceful degrade**: 미생성 종목으로의 peer 링크는 404 → 레지스트리에 있는 peer만 `<a>`, 나머지는 텍스트(`linked` 플래그).
- **goStock 클린 URL 무조건화 + stock.html 폐기**: 쿼리파라미터 페이지 제거, 모든 종목 링크 `/stocks/{code}/`.

## 알려진 갭 (후속)

- **홈 mock 랭킹 행 404**: `web/stocks/index.html` 랭킹의 미생성 종목(042700·005490·036930 등) 클릭 시 404. 레지스트리 확장(Phase 1a) 시 해소. 현 3종 범위에선 정상.
