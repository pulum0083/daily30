# 컨텍스트 노트 — 뉴스 retrieve-then-summarize 전환

작업 중 내린 판단과 그 이유를 계속 덧붙인다. 다음 세션이 재유도 없이 이어받기 위한 기록이다.

## 2026-08-04

### 처음 세운 가설은 틀렸다 (기록해 두는 이유: 같은 길로 다시 갈 수 있어서)
GHA 로그에서 "마이크론 헤드라인은 41일로 제외됐는데 같은 내용 catalyst는 살아남았다"를 보고,
`_drop_stale_earnings`가 `c["text"]`만 읽는 반면 `_filter_stale_catalysts`는 `c["catalyst"]`
폴백이 있다는 점을 근거로 **키 이름 변형 가설**을 세웠다. 재현 스크립트로 로그 6줄이 전부
설명돼서 확정한 줄 알았다.

실제 원인은 달랐다. 라이브 계측(`generate_content` 응답을 그대로 캡처)으로 원본을 보니
catalyst는 정상 스키마 `{date, text, ticker}`였고, `ticker`가 **"MU,AMD,QCOM"**이었다.
`_drop_stale_earnings`의 "여러 티커 중 하나라도 최근이면 유지" 규칙 + **AMD가 마침 그날
(8/4) 실적 발표(0일 전)** → `min(ages)=0` → 통과. headlines는 ticker 필드가 없어 MU만
잡혀 정상 제외된 것이었다.

**교훈**: 로그와 정합하는 가설이 유일한 가설은 아니다. 재현으로 "설명 가능"까지만 확인하고
"실제 그러함"은 원본 데이터를 잡아서 확인해야 한다. 이 경우 API 응답 캡처가 결정적이었다.

키 변형 가설은 틀렸지만 그 하드닝(`_item_text` 키 비의존화 + 정규화 경계)은 남겼다 —
실재하는 잠복 구멍이었고 비용이 낮다. 다만 **커밋 메시지·룰 문서에는 "이번 원인이 아니었다"를
명시**했다. 잘못된 원인 기록이 남으면 다음 사고 때 오진을 부른다.

### 왜 게이트를 더 만들지 않기로 했나
`_earnings_subject_tickers`로 §31은 막힌다. 하지만 그건 아홉 번째 게이트일 뿐이다.
결정적이었던 측정은 이것이다 — **응답에 출처가 0건**이다(모델 3종 확인, 프로덕션
`analyst_quotes.json` 4건 전부 URL 없음). 근거 문서가 애초에 없으니, 게이트는 "실측으로
반박 가능한 주장"만 걸러낼 수 있고 나머지(테슬라 배터리 발표 같은 것)는 원리적으로 통과한다.

그래서 사용자 결정으로 **출처 0건 = 하드 폐기**를 적용했다. 지금 뉴스 섹션은 항상 비어 있고
이슈는 실측 시장데이터로만 구성된다. 품질 저하를 감수한 선택이며, RSS 전환이 그 복구 경로다.

### 하드 게이트를 켤 때 확인한 것
`fetch_news.py --type us`를 라이브로 돌려 catalysts/headlines/key_indicators가 전부 0건이
되고 `grounding_failure`가 기록되는 것을 확인했다. `EMPTY_NEWS` 경로는 원래 있던 지원 경로라
파이프라인이 깨지지 않는다. **다만 뉴스 0건 상태에서 call_claude가 만드는 이슈 섹션의 품질은
아직 실물로 확인하지 못했다** — 다음 정규 실행(미국 21:15 / 코스피 07:25)에서 확인할 것.
품질이 기대 이하면 그건 RSS 전환을 앞당길 근거이지, 하드 게이트를 되돌릴 근거가 아니다.

### 정정 방식
로컬 `latest_us.json`이 7/27자로 stale이라 `generate_html` 재생성은 사이드바 실측을
오염시킨다(§23·§25·§28 선례). `analysis_snapshot.json` + `index.html`을 surgical 편집했다.
종목 픽 수치는 전부 실측 검증됨(MU +4.44%는 8/3 종가 829.50 대비 866.35로 확인) → 손대지 않음.
날조는 **뉴스에서 온 서사에만** 있었다.

### 중복 방지 목록이 날조 급식기였다
`_load_prev_catalysts`가 "이미 다룬 주제"로 넣어준 목록을 Gemini가 오늘의 catalysts로 그대로
복사해 돌려주는 걸 라이브로 확인했다(항목 끝에 "(참고: 직전 브리핑에서 언급된 내용으로…)"까지
붙여서). 즉 어제 실린 거짓이 오늘 프롬프트에 들어가 오늘 다시 실린다.
§25(슬롯 예시)·§28(임시 힌트)에 이은 **세 번째 재발**이다 —
**부정 예시를 프롬프트에 주입하면 반드시 출력 에코 게이트를 함께 둔다**를 룰로 올렸다.

RSS 전환 후에도 이 함정은 남는다. 목록 인덱스 참조 방식이면 에코가 구조적으로 불가능해지지만,
프롬프트에 "이건 하지 마" 예시를 넣는 순간 다시 생긴다. 2단계 프롬프트 설계 시 주의.

### 1단계 직후 — RSS가 무엇을 주는지 실물로 확인했다
공용 모듈 스모크 테스트로 8/4 US 쿼리를 돌렸더니 **12개 언론사가 같은 사건**을 보도하고
있었다 — 미국의 이란 공격 취소 → 중동 긴장 완화 → 유가 급락 → 위험선호 회복 →
나스닥 +2.13%, 반도체 피크아웃 우려 완화. 발행시각(01:36~08:38)도 전부 실데이터고,
원문 URL 리졸브·발행일 재확인까지 통과했다.

수집된 수치가 **사이드바 실측과 정확히 일치**한다(나스닥 +2.13%; 유가 급락은 실측 대조
게이트가 잰 WTI -3.4%와 부합). 반면 같은 날 google_search 수집이 내놓은
마이크론 실적·테슬라 배터리·7월 고용에는 **실제 원인이 하나도 없었다.**

두 가지를 했다.
1. 1차 정정본의 "검증된 뉴스는 확인되지 않아" 서술은 이제 거짓이므로 실제 원인 + 출처
   링크로 교체했다. 내가 쓴 문장이라도 틀린 걸 알고 두면 §0 위반이다.
2. 이슈 카드 출처 링크(계획 3단계)를 이 페이지에 선행 적용했다. 렌더 형태를 미리 봐 두면
   3단계에서 템플릿 작업이 수월하다.

**2단계 설계에 반영할 것**: RSS 결과가 이렇게 균질하면(같은 사건 12건) 중복 제거 후
실제 남는 소재는 2~3건이다. `is_dup_title`로 묶고 **가장 이른 발행 기사를 대표로** 삼되,
보도 매체 수를 신뢰도 신호로 쓸 수 있다(1곳만 보도한 소재는 후순위). 다만 매체 수를
"사실 여부"로 해석하면 안 된다 — 통신사 기사를 그대로 받아쓴 것도 여러 건으로 잡힌다.
