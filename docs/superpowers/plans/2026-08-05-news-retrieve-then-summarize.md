# 뉴스 수집 구조 전환 — retrieve-then-summarize (미국 브리핑 우선)

작성: 2026-08-04 · 계기: §31 실사고(6/24 마이크론 실적이 8/4 브리핑 1번 이슈로 발행)

## 왜 하는가

`fetch_news.py`는 "LLM에게 검색시켜 사실을 JSON으로 받는" 구조다. 측정 결과 **어떤 모델도
응답에 출처를 붙이지 않는다**.

| 모델 | 검색 쿼리 | grounding_chunks |
| --- | --- | --- |
| gemini-2.5-flash-lite (현행) | 2건 발행 | **0건** |
| gemini-3.6-flash | 없음 (metadata None) | — |
| gemini-pro-latest | 없음 (metadata None) | — |

프로덕션도 같다 — `data/analyst_quotes.json` 4건 전부 URL 없음. 반면 **RSS로 직접 수집**하는
`fetch_ib_korea_views.json`은 2건 전부 실제 원문 URL을 갖는다. 같은 저장소에 대조군이 있고
차이는 모델이 아니라 **아키텍처**다.

§22·§24·§25·§27·§28·§29·§31에서 여덟 번 게이트를 덧댔다. 전부 "생성된 거짓을 사후에 반박"하는
방식이라, 반박할 실측이 있는 주장만 걸러지고 나머지는 통과한다. §31에서는 **실적 발표일이라는
실측 대조가 있었는데도** 방관자 티커 하나(AMD가 그날 실적 발표)로 뚫렸다.

2026-08-04 결정으로 **출처 0건 = 뉴스 전체 폐기**가 적용됐다. 즉 지금 미국·코스피 브리핑의
뉴스 섹션은 항상 비어 있고, 이슈는 실측 시장데이터로만 구성된다. 이 계획은 그 상태를
**실제 기사 기반 뉴스**로 복구하는 작업이다.

## 목표 상태

```
① 수집(코드): Google News RSS로 실제 기사 목록 확보 — 제목·발행일시·원문 URL이 실데이터
② 검증(코드): 발행 시각 창(브리핑 타입별) 밖 기사 제외, 원문 발행일 재확인
③ 요약(LLM): Gemini는 ①의 목록에서 **고르고 요약만** 한다. 인덱스로 참조하게 해
   목록에 없는 사건은 구조적으로 출력할 수 없게 만든다
④ 게이트: 선택된 인덱스가 실제 목록 범위인지 검증. 범위 밖·미참조 항목은 폐기
```

핵심 불변식 — **날짜·사건·URL은 전부 RSS 실데이터에서 나온다. LLM은 생성하지 않는다.**
`fetch_news_live.py`가 §10에서 이미 전환한 구조이며, `fetch_ib_korea_views.py`도 동일하다.

## 재사용할 기존 자산

| 자산 | 위치 | 역할 |
| --- | --- | --- |
| `_fetch_rss(url, today, max_items)` | `fetch_news_live.py:64` | RSS 파싱 + 오늘 날짜 필터 |
| `_GN_KR` / `_GN_EN` | `fetch_news_live.py:100` | Google News RSS 엔드포인트 |
| `filter_after_market_open()` | `fetch_news_live.py:436` | 발행 시각 창 게이트(§29) |
| `_parse_real_published_at()` | `fetch_ib_korea_views.py` | 원문 실제 발행일 재확인(§Google News pubDate 불신) |
| `_resolve_gnews_url()` | `fetch_ib_korea_views.py` | Google News 링크 → 발행사 원문 URL |
| `_is_dup_title()` | `fetch_news_live.py` | 어절 + 문자 2-gram 중복 판정(§29) |

공용화가 필요하다 — 세 스크립트가 같은 일을 각자 하고 있다(§30 "판정 로직을 두 번 쓰지 않는다").
`scripts/news_sources.py`로 추출한다.

## 단계

### 1단계 — 공용 모듈 추출 (선행, 동작 변화 없음)
`scripts/news_sources.py` 신설. `_fetch_rss`·`_GN_*`·URL 리졸브·원문 발행일 재확인·중복 판정을
옮기고, `fetch_news_live.py`·`fetch_ib_korea_views.py`가 그것을 호출하도록 교체.
**기존 테스트가 전부 통과해야 한다** — 이 단계는 리팩터링일 뿐 동작이 바뀌면 안 된다.

### 2단계 — 미국 브리핑 수집기 전환
`fetch_news.py`에 `--source rss` 경로 추가(미국 타입 한정). 쿼리 세트는 §19 기준
(빅테크·반도체·장비·금융·헬스케어·소비재 실적 + 프리마켓 반응 + 매크로).
Gemini 프롬프트는 기사 목록을 번호와 함께 주고 `{"idx": n, "text": "…"}`만 받는다.
`text`에 목록에 없는 고유명사·수치가 들어가면 폐기(§0).

### 3단계 — 출처 표시
catalyst마다 원문 URL을 보존하고 브리핑 이슈 카드에 출처 링크를 단다.
사용자가 직접 검증할 수 있게 하는 것이 이 사고의 최종 방어선이다.

### 4단계 — 검증 후 확대
US에서 1주 운영하며 이슈 품질·수집 실패율을 확인한 뒤 `kospi`·`kospi-close`로 확대.

## 위험과 판단

- **RSS가 빈손인 날이 생긴다.** 그때는 뉴스 없이 발행한다 — 지금과 같은 상태이므로 후퇴가 아니다(§27).
- **Google News `pubDate`는 신뢰하지 않는다.** 오래된 기사를 재크롤링하며 현재 시각으로 다시
  찍는 사례가 2026-07-13·07-14 두 번 있었다. 원문 발행일 재확인이 최종 판정이다.
- **요약 단계 LLM도 여전히 거짓말할 수 있다.** 그래서 목록 인덱스 참조를 강제하고, 출력 텍스트에
  목록에 없는 고유명사가 등장하면 폐기한다. "생성 금지"를 프롬프트로만 걸면 샌다(§22·§24·§25 교훈).
- **1단계를 건너뛰고 2단계부터 하고 싶은 유혹.** 그러면 같은 로직이 세 벌이 되고, §30처럼 한 벌만
  고쳐진 채 나머지가 몇 주 방치된다. 선행한다.
