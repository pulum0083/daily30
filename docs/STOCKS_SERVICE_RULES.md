# 종목 서비스 운영 규칙 (Stock Page Engine)

> 브랜치 `feature/stock-page-engine` 전용 룰. `SERVICE_RULES.md`(브리핑 파이프라인)와 **분리** 관리한다.
> 머지 시 두 문서를 통합하거나 `CLAUDE.md`의 `@import`에 추가한다.
>
> 적용 범위: `/stocks` 허브 · `/stocks/{code}` 종목 상세 · ETF 상세 · 패시브 노출도 · 배당 인컴 설계기.

---

## 0. 데이터 정합성 (최상위 — `SERVICE_RULES.md §0` 계승)

> **화면에 표시되는 모든 수치는 실측이어야 한다. LLM이 생성한 숫자는 신뢰하지 않는다.**

- 가격·등락률·MA·수급·분배율·AUM·비중 등 모든 수치는 토스 Open API / 네이버 / yfinance가 **그 시점에 수집한 실측값만** 허용한다.
- 수집 실패·미검색 데이터는 표시하지 않는다. 빈 값으로 두거나 섹션을 생략한다. **추정·보간·하드코딩 금지.**
- **한국 종목은 6자리 코드만 사용. `.KS`/`.KQ` 접미사 금지** (yfinance가 KOSDAQ 유령 데이터 반환).
- 실측 소스가 없는 영역은 수치를 표시하지 않는다 (예: iNAV 괴리율 — 장중 실시간, 무인증 소스 없음 → 제외).

## 1. 포지셔닝 · YMYL (해자이자 법적 방어)

- 구글 금융 콘텐츠는 최엄격(E-E-A-T) 심사 대상이다. **면책·출처·"실측 기반" 문구를 페이지마다 고정 노출**한다.
- **의도적으로 99%/1% 같은 극단 확률을 만들지 않는다** (겸손한 신뢰도).
- AI 생성 스핀 텍스트가 아닌 실측 데이터 기반임을 방어 논리로 삼는다.
- 누적 예측 적중률은 **보수적·정직하게** 표시한다 (부풀리기 역효과).

## 2. 2티어 신호 — 라벨로 명확히 구분 (YMYL 핵심)

| 티어 | 뱃지 | 의미 | 범위 |
| --- | --- | --- | --- |
| **티어1 · Claude 예측** | `AI N%` (파란 채움) | `call_claude` 종합 예측(`up_pct`) | 그날 픽 2~4종목 + 지수 |
| **티어2 · 기술신호** | `신호 N%` (외곽선) | 규칙 기반 기술 점수 | 레지스트리 전 종목 |

- 티어1·티어2는 **다른 지표**임을 라벨·면책으로 분명히 한다. "신호"는 예측이 아닌 기술적 참고치다.
- 픽된 종목은 티어1로 격상(티어2 점수 대체).

### "AI 오늘의 전망" 카드 (종목 상세 · 티어1 전용)

- **표시 조건: 해당 날 코스피 브리핑 `stock_picks`에 포함된 종목만.** 픽이 없는 날 또는 미픽 종목은 이 카드를 숨기고 기술신호(§3)로 대체한다.
- **시간대별 상태:**

  | 시간대 | 카드 내용 |
  | --- | --- |
  | 07:30 ~ 15:29 (장 전·장 중) | 예측 배지·게이지·확률 + "→ 장 마감 후 상태 보기" 버튼 표시 |
  | 15:30 ~ 22:59 (장 마감 후) | 결과 카드 전환 (적중/미적중·실제 등락률). "→ 장 마감 후 상태 보기" 버튼 유지 |
  | 23:00 이후 (당일) | 결과 카드만. **"→ 장 마감 후 상태 보기" 버튼 제거** — 결과가 정착된 이후 CTA는 노이즈 |
  | 과거 날짜 페이지 | 결과 카드 정적 표시 (버튼 없음, 폴링 없음) |

- `data-actual-pct`가 비어 있으면 결과 카드 자리에 "결과 집계 중…" 표시. 다음 날 09:10 `check_accuracy.py` 실행 후 자동 주입.

### 참고 데이터 레이어 — 개별종목 상세 (2026-06-14 확정)

신뢰·완성 레이어. **차별점이 아니라** 페이지를 "제대로 된 종목 페이지"로 보이게 해 thin-content/E-E-A-T 방어에 기여한다. 해자는 어디까지나 적중률·패시브노출도(§4·§6)다.

- **전부 네이버 무인증 실측으로 직접 fetch한다. 칩보드 앱(`/chips`, 외부 프록시) 의존 금지** — 외부 오리진·테마 단절은 반면교사.
- 범위: **KOSPI200 전체, show-when-present** (커버리지 없는 극소형은 해당 필드 자동 생략 — §0). 상위 50 같은 별도 티어를 만들지 않는다(head term은 SEO 최악 경쟁, 롱테일 논지와 배치).

| 필드 | 소스 (네이버 무인증) |
| --- | --- |
| 시가총액 | `integration.marketValue` |
| 52주 범위 | `integration` / 일봉 |
| 외국인·기관·개인 수급 | `integration.dealTrendInfos` (5일 + 보유율) |
| 증권사 목표주가·투자의견 | `integration.consensusInfo` (`priceTargetMean`·`recommMean`) |
| 실적 분기추세 (매출·영업이익) | `finance/quarter` |

- **목표주가는 AI 전망과 대조로 제시**한다 ("AI 신호 vs 증권사 컨센서스 목표가, 현재가 대비 ±N%"). 제3자 수치이므로 **출처·기준일 명시**("네이버 금융 컨센서스 {date} 기준").
- 모든 수치는 실측. 없으면 생략(§0). 추정·하드코딩 금지.

## 3. 기술신호 점수 산식 (티어2) — 단순·투명·실측

```
score = 50
      + clamp(ma20_dist_pct,  -10, +10) × 1.0
      + clamp(ma200_dist_pct, -20, +20) × 0.5
      + (golden_cross ? +10 : -5)
      + clamp(mom_5d_pct, -10, +10) × 0.5
→ round(clamp(score, 0, 100))     # 이론 범위 ≈ 20~85
```

| 점수 | 표시 | 색 |
| --- | --- | --- |
| ≥ 58 | `신호 N%` 상승 | 파란 외곽선 |
| 43~57 | `신호 N%` 중립 | 회색 외곽선 |
| ≤ 42 | `신호 N%` 약세 | 빨간 외곽선 |
| 거래일 < 200 | `—` | 회색 |

- 모든 입력은 실측. LLM 생성 숫자 사용 금지(§0).

## 4. 랭킹

- 초기엔 **레지스트리(추적 유니버스) 내 랭킹**. "추적 N종목 중"으로 정직하게 표기한다.
- **시장 전체 톱10을 표방하지 않는다.** 유니버스 확장에 따라 시장 전체에 수렴.
- 수급↔신호 불일치("거래량 1위인데 신호 중립")는 강조 배너로 노출 — 차별 콘텐츠.

## 5. ETF 상세 페이지

- **ETF는 개별종목 AI 픽(Claude `up_pct`) 대상이 아니다.** 지수 추세 바는 하이브리드로 분기한다.

| ETF 유형 | 추세 바 소스 | 라벨 |
| --- | --- | --- |
| 코스피200 추종 (KODEX200·TIGER200·KBSTAR200·ACE200·HANARO200 등) | 그날 코스피 브리핑 `prediction`(up_pct) | "브리핑 지수 전망 연동 · 참고용" |
| 그 외 전체 (섹터·테마·해외·채권·인컴) | 티어2 기술신호(`signal_score`) | "기술 추세 신호 · 참고용" |

- **바늘 위치로만** 약세–중립–강세를 표시한다. **% 확률 숫자를 ETF 페이지에 신규 표기하지 않는다** (브리핑 예측치는 브리핑 페이지에만 — 개별종목 AI픽과 혼동 방지).
- 코스피200 추종 판별은 `etfAnalysis` 추적지수 메타가 "코스피200"인 ETF. 브리핑 미생성 시간대는 기술신호로 폴백.
- **레버리지·인버스 ETF는 추세 바 생략(`—`)** — 추세 해석 왜곡.
- 사이드바 메타는 네이버 `etfAnalysis` 실측만 (AUM·추적지수·운용사·총보수·상장일·분배). **iNAV 괴리율 표시 금지(§0).**
- 구성종목은 **TOP10 고정**. 전체 리스트는 v2(KRX·운용사 크롤, 현재 LOGOUT 차단). 섹터 비중은 TOP10 근사임을 명시("기타"가 미커버분).
- 분배·건전성은 `총수익 − 분배율` 가격침식 프록시. **ROC 명시 분해가 아님을 면책에 명시.**

## 6. 패시브(ETF) 노출도

- **노출도(구조적)만 표시한다. 인과("ETF가 종목을 움직였다") 표현 금지** — 데이터로 입증 불가.
- 지표: `passive_value = Σ(ETF_AUM × 비중)`, `concentration = passive_value / 시총`, `days_of_volume = passive_value / ADV20`.
- **두 비율(concentration·days_of_volume)을 AND 결합**해 민감주를 가린다 (절대액 1위는 민감도 낮음 — 진짜 인질은 중소형 테마주).
- **역인덱스 ETF는 제외** (ETF가 다른 ETF의 구성종목으로 섞이는 경우 배제).
- 네이버는 ETF당 TOP10만 제공 → 롱테일 비중 누락(과소집계). 한계를 면책에 명시.

## 7. 배당 인컴 설계기

- **해자 = 정직 레이어.** 커버드콜 ETF의 원금성 분배를 폭로한다. 침식 프록시 = `총수익 − 분배율`.
- v1은 **ETF만**(개별 배당주 제외). 유니버스 순자산 **1천억원 이상** (이름 패턴 매칭 시 ~61종).
  - **왜 1천억인가**: 가장 악질적인 원금성 사례(PLUS 고배당주위클리커버드콜 침식 −45%, SOL 팔란티어커버드콜OTM채권혼합 −26% 등)가 1천억~7천억 구간에 집중. 기준을 높이면 도구가 폭로해야 할 함정을 오히려 숨긴다.
- **신생펀드(상장 1년 미만)는 기본 랭킹에서 분리한다.** 분배율 TTM·총수익(Y1)이 부정확해 건전성 판정이 불가(`?`)하므로, 기본 랭킹에 섞지 않고 별도 영역에 "건전성 판정 보류"로 표기한다. 판별은 `listedDate` 기준(`is_new_fund`).
- **시뮬레이터는 보유 입력을 저장하지 않는다** (정적 서빙·SEO 닫힌루프 회귀 방지). 트래커가 아니다.
- 침식 프록시는 강세장에서 둔감하다 — 임계 보정 필요(가격 시계열 교차검증은 v2).

## 8. 구조 · 라우팅 · SEO

- **종목 서비스가 메인, 브리핑이 보조.** 홈(`/`) = `/stocks` 허브. 종목 허브가 검색 유입의 정문.
- **이 저장소 안에서 구현.** 새 레포 분리 안 함(데이터가 여기서 생산됨). 신규 폴더만 분리 — `web/stocks/`, `scripts/templates/stocks/`. (칩보드식 외부 프록시 = 오리진 분리로 테마·데이터 단절. 반면교사.)
- `/stocks/{code}/` **영구 URL** — 닫힌 푸시 루프 → 열린 검색 루프. sitemap·JSON-LD 필수.
- 종목↔종목 상호 링크(섹터·ETF 조합)로 내부 링크 그래프를 만든다.
- 에셋은 `/assets/` 경로만. `/v2/` 경로 발생 금지.

### 페이지 생성·확장 전략 (2026-06-14 확정)

- **빌드타임 일괄 생성만.** 온디맨드(클릭 시 생성)는 금지 — 정적 서빙 구조에서 페이지가 없으면 구글이 색인할 대상이 없어 검색 루프가 안 돈다.
- **개별종목·ETF 모두 영구 일괄 생성.** 픽 자연누적 단독 방식은 닫힌 루프 회귀라 폐기. 레지스트리는 KOSPI200 등 기준 유니버스를 일괄 시드하고, 픽은 그 위에 누적한다.
- **단계적 롤아웃** (구글 scaled-content-abuse 정책 방어 — 대량 템플릿 페이지 일시 투입 금지):

  | 단계 | 범위 | 게이트 |
  | --- | --- | --- |
  | **Phase 1a** | 개별종목 KOSPI200 + ETF 1조+(104) ≈ 300페이지 | 색인·JSON-LD 정상 + 수동 페널티 없음 확인 |
  | **Phase 1b** | ETF 1천억+(466) · 개별종목 KOSDAQ150 추가 ≈ 800페이지. 인컴 설계기도 1천억 유니버스로(§7) | 1a 색인 확인 후 ~4–8주 |
  | **Phase 2** | 롱테일(5백억 ETF), 교육 콘텐츠 | — |

- **최소 콘텐츠 기준.** 차별 데이터(분배 건전성·패시브 노출도·기술신호·AI 픽 이력) 중 **하나도 못 채우는 페이지는 발행하지 않는다.** 가격+MA만 있는 빈약한 페이지 금지.
- **갱신 부하**: 초기엔 전체 일별 갱신(~1,300 calls/일, 토스로 감당). 부하가 실제로 문제될 때만 티어별 차등 갱신 도입(조기 최적화 금지).

## 9. 검증 기준 (발행 전)

1. **레지스트리** — 당일 등장 종목이 `stock_universe.json`에 누적, 코드 매핑 실패 종목 제외.
2. **데이터 갱신** — `stock_pages.json` 가격이 실측과 일치(`validate_analysis` 대조). `.KS`/`.KQ` 미사용.
3. **페이지 생성** — 픽 종목은 AI 전망 풀세트, 비픽 종목은 기술 지표만. `/v2/` 미발생.
4. **라우팅·sitemap** — `/stocks/{code}/` 접근 가능, sitemap 포함, JSON-LD 유효.
5. **적중률 기록** — `check_accuracy` 후 픽 종목 결과 누적.
