# 결정 기록 — 애드센스 준비

## 왜 외부 진단을 그대로 실행하지 않았나

제미나이 진단은 사이트 밖에서 본 추정이라 검증 없이 실행하면 엉뚱한 곳을 고치게 된다.
실측해보니 절반가량이 실제와 달랐다.

- **"브리핑이 thin content"** → 실제 4,602자. 틀렸다.
- **"푸터 법적 고지가 갖춰져 있어 매우 좋다"** → 존재는 하지만 **sitemap 미등재**라
  심사관·크롤러 도달 경로가 약하다. 칭찬받은 항목이 실은 손봐야 할 항목이었다.
- **"About 페이지 강화 필요"** → 이미 1,515자로 데이터 원칙까지 서술돼 있다.
- **"/briefings/ 리다이렉트"** → 유일하게 확실히 맞았고, 실제로는 더 심각하다
  (sitemap에 등재해 크롤러에게 26자짜리 "이동 중…" 페이지를 광고 중).

**교훈**: 외부 진단은 가설 목록으로 쓰고, 우선순위는 실측으로 다시 매긴다.

## 가장 중요한 판단 — ③이 ①을 만들었을 수 있다

진단이 "본문이 얇다"고 본 이유가 **허브에서 막혀 본문에 도달하지 못했기 때문**일 수 있다.
그렇다면 가장 싼 수정(허브 아카이브화)이 가장 큰 오해를 걷어낸다. 그래서 Tier 1에 뒀다.

## AI로 가이드를 대량 생성하지 않는다 (핵심 결정)

진단은 "사람이 직접 쓴 듯한 심층 가이드 15~20편"을 권했다. 이걸 AI로 찍어내면 구글이
금지하는 *scaled content abuse* 그 자체가 된다 — **애드센스를 통과하려고 애드센스가
금지하는 행위를 하는 자기모순**이고, 적발 시 도메인 단위 제재라 브리핑 서비스 본체가
위험해진다. 이 서비스는 §0에서 "틀린 것은 감수할 수 없다"를 제1원칙으로 두고 게이트를
9개나 쌓아왔는데, 그 원칙을 마케팅 목적으로 우회하는 셈이기도 하다.

대신 **이미 구현된 방법론을 설명하는 글**을 쓴다. 코드에 근거가 있으므로 1차 경험이고,
E-E-A-T의 Experience에 해당한다. 편수는 15~20편 → **5~8편**으로 줄인다. 얇은 20편보다
제대로 된 6편이 낫고, 얇은 20편은 오히려 thin content 판정을 부른다.

## 죽은 템플릿 발견

`scripts/templates/pages/briefings_index.html`(아카이브 목록)이 살아 있으나 어느 코드
경로에서도 렌더되지 않는다. 2026-07-22에 리다이렉트 스텁이 `web/briefings/index.html`을
덮어썼다. SERVICE_RULES §10(라이브 스코어보드·이슈 브리핑 섹션)과 같은 계열의 사고다 —
**템플릿·문서가 코드보다 오래 사는 상황.** T1-1은 새로 만드는 게 아니라 되살리는 작업에
가깝다.

## 아직 결정하지 않은 것

- **T2-1 진입/목표/손절 표기**를 (a) 문구 완화 (b) 면책 강화 (c) 근거 노출 중 무엇으로 갈지.
  현재 권장은 (c) — 근거를 보여주는 쪽이 정책 리스크와 신뢰도 양쪽에 유리하지만,
  서비스 정체성(매매 참고 신호 제공)과 맞물리므로 사용자 판단이 필요하다.
- **가이드 작성 주체.** 사람이 쓰는 걸 전제로 했으나 실제 집필 부담이 크다면 편수·범위를
  다시 잡아야 한다. AI로 찍어내는 선택지는 위 이유로 제외한다.
