# 09:00 장중 이슈가 어제 장 요약 기사를 발행한 사고 — 원인과 수정 계획

작성: 2026-07-30

## 증상

`https://doubleshot.space/stocks` 브리핑 스트립의 "장중 이슈" 09:00 항목이
어제(7/29) 장 내용을 오늘의 장중 이슈로 보여줬다.

| 09:00 발행분 | 어제(7/29) 발행분 |
| --- | --- |
| 코스피·코스닥 또 동반 급락…사상 첫 이틀 연속 서킷브레이커 발동 | (14:01) 코스피·코스닥 이틀째 동반 서킷브레이커…국내 증시 '패닉 장세' |
| 노무라 "코스피 급락 배경은 외국인 대규모 매도와 국민연금 매수세 약화" | (15:01) 노무라 "코스피 급락 배경, 외인 대규모 매도·국민연금발 수급공백" |

즉 어제 이미 발행한 두 이슈를 제목만 바꿔 오늘 09:00 "장중 이슈"로 다시 낸 것이다.
`market` 항목의 원문 URL은 `viva100.com/article/20260729501199` — 기사 ID가 7/29다.
`stock` 항목(조선일보)의 실제 발행시각은 `2026-07-29T22:48Z` = **오늘 07:48 KST**로,
날짜만 오늘이고 내용은 어제 장 리캡이다.

## 근본 원인 (두 겹)

1. **`_fetch_rss`의 날짜 필터가 "오늘 날짜"만 본다.**
   09:00 슬롯이 도는 시점에는 장이 방금 열려 장중 뉴스가 존재하지 않는다.
   그래서 RSS가 주는 "오늘 날짜" 기사는 전부 **새벽에 발행된 어제 장 리캡**이다.
   기존 3시간 컷오프(`cutoff = now - 3h`)는 09:00 실행 시 06:00이 되어 새벽 리캡을 그대로 통과시킨다.

2. **중복 제거가 오늘 발행분만 대상으로 한다.**
   `all_today_titles`는 `existing.get("date") == today`일 때만 채워진다.
   09:00은 그날 첫 실행이라 이 목록이 비어 있어 사전 필터(`_filter_seen_articles`)와
   사후 검사(`_find_duplicate`)가 모두 무력화된다 — 어제 발행분과 사실상 동일한 기사를
   막을 근거가 코드에 없다.

## 수정

**A. MARKET 슬롯은 장 개시 이후 발행 기사만 채택한다 (근본).**
장중 이슈는 정의상 장이 열린 뒤의 뉴스다. `pub_time < 09:00`인 기사는 어제 장 리캡이므로 제외한다.
09:00 정각 실행은 이 게이트로 거의 항상 빈손이 되는데, 그게 정상이다 —
개장 직후엔 장중 이슈가 없다. 빈손이면 발행을 생략하고, 화면은 오늘 코스피 예측 브리핑으로
폴백한다(§13). **완전성보다 정합성이 우선이다(운영 규칙 0).**

**B. 중복 제거 대상에 어제 발행분을 포함한다 (보강).**
`kospi-news-{어제}.json`의 `seen_titles` + history 타이틀을 dedup 목록에 합친다.
A를 통과한 기사(장중에 어제 서사를 재보도한 기사)도 이 단계에서 걸러진다.
저장되는 `seen_titles`에는 어제 타이틀을 넣지 않는다 — dedup 입력으로만 쓴다.

## 검증

- `scripts/test_market_session_gate.py` — A/B 각각의 단위 테스트 + 실사고 데이터 리플레이.
- 기존 `scripts/test_bump_latest_time.py` 회귀 통과.
- 오늘자 09:00 항목 제거 후 현재 시각으로 재수집해 실제 장중 기사가 잡히는지 확인.

## 범위 밖

- cron 스케줄 변경(09:00 슬롯 자체 제거)은 하지 않는다 — 트리거는 cron-job.org 외부 설정이고,
  게이트만으로 잘못된 발행을 막을 수 있다.
- 이미 발송된 텔레그램은 되돌리지 않는다(§16). 이 사고는 웹 데이터만 영향.
