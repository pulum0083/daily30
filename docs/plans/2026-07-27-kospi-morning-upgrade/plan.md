# 코스피 아침 브리핑 개선 — 계획

작성 2026-07-27. 사용자 요청 두 건("브리핑이 미국 데이터만 얘기해서 재미없다", "오를까/내릴까 % 를 더 정교하게")에 대한 진단 결과와 실행 계획.

## 문제 진단 요약

두 문제의 뿌리가 같다 — **아침 브리핑이 "직전 미국장 종가"라는 단일 입력에 과도하게 의존한다.**

### 재미 없음

- [fetch_news.py](../../../scripts/fetch_news.py) `KOSPI_PROMPT` 검색 지시의 **84%가 미국발**. 국내 뉴스 검색 항목은 사실상 1줄(대형주 기업 이벤트).
- 2026-07-27 실제 수집 결과 `key_indicators` 5건·`catalysts` 2건이 **전부 미국발, 국내 0건**.
- `fetch_news.py`에 **요일 개념이 없다.** "어제(현지 시각) 미국"·"간밤"이 상수로 박혀 있어 **월요일 72시간 공백**(금 미국장 마감 → 월 07:25)이 검색 지시에 존재하지 않는다. §24에서 만든 `session_label`이 call_claude·validate·generate_html에만 적용되고 fetch_news에는 누락됐다.
- 코스피 `catalysts`가 plain string이라(미국은 `{date,text,ticker}` 구조화 객체) `_filter_stale_catalysts`가 "날짜 모름 → 통과" 분기로 매번 빠진다. 날짜 게이트가 사실상 무력.
- 국내 카테고리 전무 — 금통위·정책·규제·수출입·공시·코스닥·개인/기관 수급. 아이러니하게 `KOSPI_CLOSE_PROMPT`는 정책·규제·기관 수급을 검색한다(아침 프롬프트만 누락).

### 수치 부정확

- `direction`은 [leading_signal.py](../../../scripts/leading_signal.py) 결정론 prior가 뒷받침. **그러나 `up_pct`·`down_pct`·`confidence`는 정량 근거가 0** — 481줄 시스템 프롬프트 어디에도 정의가 없고, 유일한 명세는 출력 스키마 예시의 `"up_pct": 65` 한 줄([call_claude.py:396](../../../scripts/call_claude.py)). 미국 프롬프트엔 정의 문장이 있는데(`:605`) 코스피엔 없다.
- **적중률 피드백 루프 없음.** `briefings.json`은 발송 후 기록, `check_accuracy.py`는 09:10 실행 — 07:25 브리핑보다 항상 늦다. 모델이 자기 성적을 본 적이 없다.

실측(코스피 채점 72건, 2026-07-27 기준):

```
적중률                   65.3% (47/72)
"항상 상승" 단순 규칙       63.9%      ← 초과 성과 +1.4%p
Brier skill score       +0.029      ← base rate 대비 사실상 0
corr(up_pct, 실제 등락률)  +0.25
최근 20건 적중            70%  (같은 구간 always-up 45%)
```

구간별 캘리브레이션:

| up_pct | n | 실제 상승 비율 |
|---|---|---|
| 20–29 | 8 | 50% |
| 30–39 | 17 | 41% |
| 60–69 | 18 | 78% |
| 70–79 | 19 | 68% |
| 80–89 | 5 | 100% |
| **40–59** | **3** | 74회 중 3회만 사용 |

→ **하락 예측이 특히 못 맞는다.** 그리고 확률을 확률이 아니라 "확신의 표시"로 쓰고 있다(애매한 날 중간값을 안 낸다). 정의가 없으니 당연한 결과.

### 발견된 개별 결함

1. **EWY 이중계상** — EWY 등락률엔 같은 날 코스피 등락이 이미 반영돼 있다. §24 방지룰이 *서사* 차원에선 이걸 명시했으나 **prior 계산엔 미반영**. 2026-07-24 예: 코스피 -5.72%, EWY -6.27% → 진짜 신규 정보는 잔차 -0.55%인데, 현재는 `-6.27 × 0.3 = -1.88`이 통째로 score에 들어가 그것만으로 `DN_BAND(-1.2)`를 넘긴다.
2. **NQ 가중치 0.3은 피팅된 적이 없다** — 백테스트가 과거 선물을 복원 못 해 제외했고([diagnose_direction_signals.py:76](../../../scripts/diagnose_direction_signals.py)) 손으로 넣은 값이다. 그런데 **07:25 시점에 유일하게 실시간인 신호가 NQ다**(SOX·나스닥·EWY는 6시간 이상 묵은 종가). 미국 브리핑 prior는 선물에 1.0을 주며 "프리마켓 선물이 가장 신선"이라 주석까지 달아뒀는데 코스피 prior만 그 논리를 안 따랐다.
3. **ES=F·YM=F가 코스피 경로엔 수집조차 안 된다** — 미국 경로에만 있다([fetch_data.py:777](../../../scripts/fetch_data.py)).
4. **선행신호가 아카이브되지 않는다** — `web/data/market-{date}.json`엔 코스피 등락률만 저장. prior의 실전 성적을 사후 추적할 방법이 없다.
5. **`supply_history.json`이 프롬프트에 최근 1일치만** 들어간다(파일엔 추세가 다 있다).
6. **`signal_history_kospi.json` 다양성 가이드가 3주째 죽어 있다** — 현재 모든 출력 포맷이 `reasons` 필드를 안 내는데 `extract_signal_emojis(analysis["reasons"])`가 빈 배열을 받아 저장이 early-return 한다. 2026-07-09 엔트리가 계속 재생된다.

## 실행 계획

세 트랙. 사용자가 셋 다 선택했다(2026-07-27).

### Track A — 재미: 국내·주말 이슈 수집

목표. 아침 브리핑에 **오늘 국내 소재**와 **주말 공백 구간 이벤트**가 실제로 들어간다.

- **A1. 세션 갭 인식** — `fetch_news.py`에 `session_label` 적용. 프롬프트에 "직전 미국장(= 지난 금요일 7/24) 마감 이후 지금까지"라는 **명시적 창(window)** 을 주입. 월요일·휴일 다음날에 자동으로 넓어진다.
- **A2. 주말·컨퍼런스 트랙** — 글로벌 테크·정책 행사(AI 서밋·GTC·CES·잭슨홀·OPEC·G20 등)와 발언을 검색 항목에 추가. 주 5회 중 월요일 1회지만 정보 공백이 가장 큰 날이다.
- **A3. 국내 트랙** — 금통위·정책/규제·수출입 지표·공시·개인/기관 수급을 검색 항목에 추가하고, `key_indicators` 5슬롯 중 **최소 2개를 국내 몫으로 예약**.
- **A4. 국내 이슈 RSS 실수집** — [fetch_news_live.py](../../../scripts/fetch_news_live.py)의 한국어 Google News RSS(`_GN_KR`)와 [fetch_ib_korea_views.py](../../../scripts/fetch_ib_korea_views.py)의 **실제 발행일 검증**(`_parse_real_published_at`) 패턴을 재사용해 "RSS 실수집 → Gemini는 선별·요약만" 2단계 파이프라인 구성. §10에서 이미 검증된 패턴이라 날짜 세탁이 구조적으로 차단된다.
- **A5. catalysts 구조화** — 코스피 catalysts를 `{date, text}` 객체로 전환해 기존 날짜 게이트를 활성화(미국 경로와 동일 구조).
- **A6. 화면** — 국내 이슈 섹션 신설 또는 `us_issues`와 통합. **국내 소재가 없는 날은 섹션 생략**(운영 규칙 0 — 없으면 지어내지 않음).

### Track B — 수치: 새 수집 없는 개선분

목표. `up_pct`가 "정의된 확률"이 되고, 자기 성적을 보고 보정된다.

- **B1. `up_pct` 정의 명문화** — 미국 프롬프트(`:605`)의 정의 문장을 코스피에도 도입. "오늘 코스피가 **전일 종가 대비 상승 마감**할 확률". `confidence`가 무엇을 재는 값인지도 정의. **근거가 갈리는 날 40~59 사용을 강제**.
- **B2. 캘리브레이션 피드백 주입** — `briefings.json`에서 구간별 실적표를 계산해 프롬프트에 주입. 이때 **채점 완료 항목만** 사용하고, 미채점 항목을 옛 결과로 대체하지 않는다(§16 방지룰).
- **B3. EWY 잔차화** — `leading_signal.py`에서 `EWY잔차 = EWY% − 코스피당일%`(환율 조정)로 교체. 이중계상 제거.
- **B4. 선물 신선도 반영** — `ES=F`·`YM=F`를 코스피 경로 수집에 추가하고, `SIGNAL_WEIGHTS`의 `nq` 가중치를 상향. **가중치 변경은 백테스트로 검증한 뒤에만 확정한다**(B7 선행).
- **B5. 선행신호 아카이브** — `web/data/market-{date}.json`에 SOX·EWY·NQ·ES·환율·prior score·prior direction을 함께 저장. 사후 캘리브레이션의 전제 조건.
- **B6. 수급 추세 주입** — `supply_history.json`의 5~7일 추세를 프롬프트에 주입(파일은 이미 있다).
- **B7. 백테스트 재실행 & 가중치 재피팅** — 로컬은 사내 프록시 SSL 때문에 yfinance가 막힌다. **GitHub Actions에서 실행**해야 한다. B4의 가중치 변경은 이 결과로 확정.
- **B8. (후속) up_pct 결정론화** — prior score → 확률 로지스틱 매핑. B5 아카이브가 쌓여야 제대로 피팅되므로 초기엔 규칙 기반 밴드로 시작하고, LLM에겐 ±10%p 조정만 허용.

### Track C — 코스피200 야간선물

목표. 07:25 시점 **시장 자신의 코스피 시가 예측값**을 prior에 넣는다.

- **C1. 데이터 소스 조사** — EUREX 코스피200 연계상품 거래 여부·시간·무료 접근 경로, CME 상장 여부, 대안(한국물 ADR·NDF 원달러·MSCI Korea ETF)의 실현 가능성. **조사 진행 중.**
- **C2. 수집 구현 + prior 편입** — C1 결과에 따라 결정. 소스가 확인되지 않으면 대안(ADR 바스켓 등)으로 대체하거나 트랙을 보류한다. **존재가 불확실한 API·티커를 추측으로 넣지 않는다**(운영 규칙 0).

## 검증 기준

| 트랙 | 성공 판정 |
|---|---|
| A | 월요일 브리핑에 금~일 사이 이벤트가 실제로 등장. `news_summary_kospi.json`의 `key_indicators`에 국내 항목 ≥2건. 국내 소재 없는 날 섹션이 깨끗이 생략됨 |
| B | `up_pct` 40~59 사용 비율이 유의미하게 증가. Brier skill score가 현재 +0.029 대비 개선. 하락 예측(up_pct<40) 구간 정밀도가 41~50% 대비 개선 |
| C | 07:25 시점에 실제로 갱신된 값이 조회됨(전일 종가가 아님). 백테스트로 prior 기여도 확인 |

**공통.** 모든 변경은 기존 테스트를 깨지 않아야 하고, 새 게이트·수집기에는 테스트를 함께 붙인다(§22·§24 선례 — 프롬프트 지시만으로는 새기 때문에 게이트가 최종 방어선이다).

## 리스크

- **A4·C2는 외부 소스 의존** — 수집 실패 시 섹션 생략으로 안전하게 degrade 해야 한다. 파이프라인을 막으면 안 된다(`continue-on-error` + 빈 배열 폴백).
- **B4 가중치 변경은 실전 예측을 직접 바꾼다** — 백테스트 없이 손으로 조정하지 않는다. 이게 NQ 0.3이 검증 없이 들어간 원인이다.
- **로컬 yfinance 차단** — 사내 프록시 SSL 인증서 문제로 백테스트·실측 검증이 로컬에서 불가. GHA 경유가 필요하고, 이는 반복 주기를 느리게 만든다.
- **A는 Gemini 검색 품질에 의존** — 프롬프트를 고쳐도 검색이 국내 소재를 못 물어오면 효과가 없다. 그래서 A4(RSS 실수집)가 프롬프트 수정(A1~A3)보다 근본적이다.
