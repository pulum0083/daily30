# 컨텍스트 노트 — 자금 지도 확장 패널 (C-2)

작업 중 내린 판단과 그 이유. 다음 세션이 같은 고민을 반복하지 않도록 남긴다.

## 왜 목업을 먼저 만들었나

사용자가 "화면을 보고 판단하고 싶다"고 했고, 실제로 목업이 **구현 전에 설계 결함 2건을
잡아냈다**. 텍스트 제안만 봤으면 그대로 구현됐을 것들이다.

1. **집중도 130%** — 분모를 net으로 잡았는데, 방향이 갈린 테마(반도체)에서 상위 5개
   |flow| 합이 net을 넘어 100%를 초과했다. 화면에 띄우고 나서야 보였다.
2. **종목명 충돌** — 2단 분할에서 폭이 좁아 브랜드 접두어를 뗐더니
   `KODEX AI반도체TOP2플러스`와 `SOL AI반도체TOP2플러스`가 둘 다 `AI반도체TOP2플러스`가 됐다.
   두 종목은 **서로 반대 방향**(+520억 / −843억)이라, 가장 흥미로운 사실이 가려졌다.

목업은 실데이터로 만들었다. 가짜 숫자로 만들었으면 둘 다 못 봤다.

## 일별 NAV vs 최종 NAV — 왜 최종 NAV인가

처음엔 각 날의 NAV로 일별 흐름을 계산했다. 자연스러워 보였지만 일별 합이 헤더 누적과
**최대 17.9% 어긋났다**(반도체 1,748 vs 2,129). 사용자가 막대를 더하면 헤더와 다른 숫자가
나온다 — 한 화면 안에서 숫자가 서로를 부정하는 상황이고, 이 서비스는 그걸 결함으로 본다
(SERVICE_RULES §28 "본문 수치를 같은 페이지 사이드바와 대조", §30 "한 화면 안의 모순").

최종 NAV로 통일하면 telescoping이 성립해 정확히 일치한다.

```
Σ(shares[d] − shares[d−1]) × nav_final = (shares[last] − shares[first]) × nav_final
```

실히스토리 검증 결과 오차가 **최대 381억 → 최대 2억**(순수 반올림)으로 줄었다.

**대안을 버린 이유**: 누적값을 일별 합으로 재정의하는 방법도 있었지만, 타일에 표시되는
기존 숫자가 전부 바뀌어 영향 범위가 너무 크다.

## carry-forward가 필요한 이유

중간 스냅샷에 없는 종목을 건너뛰면 telescoping이 깨진다. 좌수 0으로 보면 **없는 유출이
만들어진다**(운영규칙 0 위반). 직전 좌수를 유지 = "그날 변화 없음"이 유일하게 안전한 해석이다.

## 겪은 함정 — 로컬 CSS 캐시

로컬 `python3 -m http.server`는 `no-cache` 헤더를 안 보내서 `stocks-home.css?v=6`이
캐시된 채로 남아, 새 CSS 규칙이 하나도 안 먹은 화면을 한참 봤다. 잠깐 `?v=` 범프가
필요한 프로덕션 문제로 오해했는데, 확인해보니 **vercel.json이 `/assets/*.(css|js)`에
`no-cache, must-revalidate`를 이미 보내고 있어** 실제 배포엔 영향이 없다.

→ 로컬에서 에셋 수정이 안 먹는 것처럼 보이면 **먼저 캐시를 의심**할 것. `?dev=<timestamp>`로
link 태그를 교체하면 바로 확인된다. 프로덕션 헤더는 `curl -sI`로 직접 볼 것.

## 헤드리스 브라우저에서 확장 애니메이션이 안 열린다

`openExpand()`가 `requestAnimationFrame` 안에서 `.open`을 붙이는데, 이 헤드리스 환경에선
rAF가 발화하지 않아 패널이 `height:0`인 채로 남는다. **프로덕션(변경 전 코드)도 동일하게
재현**되므로 이번 변경의 회귀가 아니다. 검증할 땐 `ex.classList.add('open')` +
`style.height='auto'`로 강제로 열고 봤다.
