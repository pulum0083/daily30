# 계측 공백 메우기 — 행동 이벤트 수집

## 배경

2026-08-22 진단 중 "사용자 정체"를 확인하려다 계측 상태를 전수 점검했다.
**수집은 망가지지 않았다** — 오해를 먼저 정정한다.

| 층위 | 상태 | 근거 |
| --- | --- | --- |
| GA4 태그 발화 | ✅ 정상 | 라이브에서 `google_tag_manager` 로드 확인, `dataLayer`에 `js`·`config`·`event:page_view` 푸시됨 |
| 페이지 커버리지 | ✅ 전 페이지 | 저장소 내 발행 HTML 중 태그 누락 0건 |
| 홈 가상 pageview | ✅ 정상 | `send_page_view:false` + `dsTrackPageview()` 수동 전송. 최초 진입·해시 복원·`go()` 전환 모두 커버 |
| **행동 이벤트** | ❌ **0건** | `gtag('event', …)` 호출이 `page_view` 하나뿐 |
| `/api/visitors` 조회 | ❌ 503 | 자격증명 4개 미설정. **수집이 아니라 조회 경로** |

## 문제

pageview만으로는 진단의 핵심 질문에 답할 수 없다.

- 진단 §치명1(발견→이해 루프 절단): 종목을 눌렀다가 "상세 페이지를 제공하지 않아요" 토스트로
  튕기는 횟수. **이건 페이지 이동이 아니라서 pageview에 흔적이 안 남는다.** 막다른 길이
  하루 몇 번 발생하는지 지금은 알 방법이 없다.
- 검색이 43/46을 거절하는데, 사람들이 실제로 뭘 검색하는지 모른다 —
  상세 페이지를 어느 종목부터 되살릴지 정할 근거가 없다.
- 텔레그램 구독이 유일한 재방문 채널인데 클릭률을 모른다.

## 범위 (최소)

이벤트 4종만 추가한다. 전부 기존 함수 한 곳을 지나므로 배선 지점이 적다.

| 이벤트 | 위치 | 답하는 질문 |
| --- | --- | --- |
| `stock_detail_blocked` | `stocks-home.js goStock()` else | 막다른 길이 실제로 몇 번 발생하나 |
| `stock_detail_open` | `stocks-home.js goStock()` if | 성공 클릭 대비 차단 비율 |
| `search` | `stocks-home.js renderSearch()` | 무엇을 검색하나 · 결과 유무 |
| `telegram_click` | `main.js` · `stocks.js` 위임 리스너 | 유일한 재방문 채널 전환율 |

`goStock()`은 홈의 모든 종목 클릭(신호·랭킹·검색·주도주 9개 호출부)이 지나는 단일 관문이라
**한 곳만 고치면 전부 계측된다.**

## 하지 않는 것

- **`/api/visitors` 자격증명 설정** — 시크릿은 코드로 다루지 않는다. 사용자가 직접 발급·등록.
  또한 이 API는 총 페이지뷰 숫자 하나를 사이드바에 띄우는 위젯이라 진단 가치가 거의 없다.
  "유입이 어디로 / 이탈이 어디서"는 GA4 콘솔에서 보는 것이지 이 API가 아니다.
- **동의 배너 추가** — 현재 없고, 이번 변경은 수집 항목의 성격을 바꾸지 않는다(개인정보 없음).
- 새 파일·새 스크립트 요청 — 기존 파일에 최소 라인만 추가한다(CLAUDE.md §2·§3).

## 개인정보

전송 파라미터는 종목코드·종목명·검색어(종목명/코드)뿐이다. 개인 식별 정보 없음.
검색어는 GA4 권장 이벤트 `search`의 표준 파라미터 `search_term`을 그대로 쓴다.

## 검증

라이브 페이지에서 `goStock()`을 차단 종목·허용 종목으로 각각 호출하고
`dataLayer`에 해당 이벤트가 정확히 1건씩 쌓이는지 확인한다(단언이 아니라 실측).
