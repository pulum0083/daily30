# 미국 이슈 결과 스코어보드 — 설계

작성 2026-09-06. 프로토타입 `docs/prototypes/2026-09-06-kospi-briefing-with-scoreboard.html`
(빌더 `2026-09-06-kospi-scoreboard-builder.py`), 3안 비교본 `2026-09-06-us-issue-scoreboard.html`.

## 배경

미국 브리핑(21:15 KST)은 "오늘 점검할 이슈" 4~5장을 내건다. 각 카드는 산문이 아니라
`up`/`down` × `{label, tickers}` 구조라 **방향 주장이 검증 가능한 형태로 이미 저장돼 있다**.
그 결과를 다음날 코스피 아침 브리핑(07:25)에서 같은 카드 형식으로 채점해 보여준다.

타이밍이 맞는다 — 그 이슈들이 가리키는 미국 정규장은 05~06시 KST에 마감하므로, 07:25는
마감 1.5시간 뒤다.

### 측정 가능성 (미국 브리핑 30편·이슈 134건 전수 조사)

| 유형 | 건수 | 채점 |
| --- | --- | --- |
| 티커 있음 | 84건 (63%) | 해당 티커 실측 |
| "지수 전반" 계열 | 32건 (24%) | S&P500 프록시 |
| 롱테일 라벨(원가 민감 소비재 등) | 18건 (13%) | 불가 → 카드 생략 |

## 결정 사항

| 항목 | 결정 | 근거 |
| --- | --- | --- |
| 결과의 성격 | **실측 채점 스코어보드**. LLM이 개입하지 않는다 | 숫자·판정·문구가 전부 결정론이라 §0 위반 가능성이 구조적으로 0 |
| 표현 | **C안** — 판정 배지 + 결과 한 줄 + 티커 배지 | 한 줄은 LLM 문장이 아니라 실측에서 조립한 템플릿 |
| 배치 | 기존 `us_issues` **자리를 대체**. 근거 아래·예측 위 | 프로토타입에서 미국 섹션 2개가 연달아 붙는 무게가 확인됨 |
| `us_issues` | **파이프라인에서 완전 제거** | 화면만 빼면 §10의 죽은 코드 패턴(두 번 반복된 사고)을 그대로 재현한다 |
| 중복 채점 | 같은 프록시·같은 방향이 다시 나오면 **첫 장만** 결과 표시 | 9/3 실측에서 동일 결과 2장이 실제로 발생 |
| 측정 불가 | 카드째 생략, 남는 카드 0이면 섹션 생략 | §0 — 없으면 비운다 |
| 빗나간 예측 노출 | **감수한다** | 사용자 결정. 9/3은 4장 중 3장이 '빗나감'인 날이었다 |

## 구조

```
코스피 잡: fetch_data → [score_us_issues] → fetch_news → call_claude --no-html
           → validate_analysis → call_claude --render → generate_html
```

### `scripts/score_us_issues.py` (신규)

1. 대상 세션 = `session_label.prev_us_session(브리핑날짜)`.
   미국 브리핑은 21:15 KST(=아침 ET)에 나가므로 **디렉터리 날짜(KST) = 그 브리핑이 가리키는
   ET 세션 날짜**로 일치한다. 월요일이면 자동으로 금요일이 잡힌다.
2. `web/briefings/{세션날짜}/us/analysis_snapshot.json` 의 `issues` 를 읽는다.
3. 각 side의 티커를 채점한다. 티커가 없고 라벨이 프록시 화이트리스트에 있으면 대입한다.
4. `data/us_issue_results.json` 으로 저장한다(`us_session_date`, `scored_at`, `cards`).

**날짜 고정 조회가 핵심이다.** 해당 ET 세션의 봉을 골라 직전 봉과 비교한다. "최신 봉"을 쓰면
07:25에 데이터가 아직 안 왔을 때 조용히 전전 세션 등락률이 실린다 — §24가 분모를 안 믿어서
터진 사고와 같은 계열이라 아예 날짜로 못 박는다. 재생성해도 같은 값이 나오는 건 덤이다.
**해당 날짜 봉이 없으면 그 티커를 버린다. 최신 봉으로 폴백하지 않는다.**

### 채점 규칙 (전부 결정론)

- 적중 = `up`이면 등락률 > 0, `down`이면 < 0.
- 판정 배지는 개수를 세어 만든다 — `2건 전부` / `4중 2 적중` / `빗나감`.
- 결과 한 줄은 실측에서 조립한다.
  - 단일 대상 — `{라벨}이 {올랐어요|내렸어요} · {이름} {등락률}`, 빗나갔으면 `— 예상과 반대예요`.
  - 복수 대상 — `{라벨} {n}종목 중 {h}종목이 {올랐어요|내렸어요} · 평균 {평균}`.
- 프록시를 대입한 카드는 **화면에 그 사실을 명시**한다("종목이 지정되지 않은 '지수 전반'은
  S&P500 실측으로 채점했어요"). 실측이지만 대입은 추론이므로 §41(실측과 판단을 구분해 밝힌다)을 따른다.

### `generate_html`

`build_us_issue_results(analysis, target_date)` 를 추가한다.

- **우선순위**: `analysis["us_issue_results"]`(스냅샷) → 없으면 `data/us_issue_results.json`.
  후자를 쓸 때 `analysis` 에 주입하면 `analysis_snapshot.json` 이 dict를 통째로 저장하므로
  결과가 자동으로 스냅샷에 박힌다. 새 저장 장치가 필요 없고, 재생성 시 §2 규칙대로 스냅샷이
  1순위라 다시 조회하지 않는다.
- **날짜 게이트**: 결과의 `us_session_date` 가 `prev_us_session(대상일)` 과 다르면 버린다.
  다른 실행이 남긴 파일이 엉뚱한 날짜 브리핑을 오염시키는 것을 막는다(§14와 같은 처방).
- 템플릿 `sections/us_issue_results.html` 을 새로 만든다. 항목 0이면 섹션 자체가 없다.

### 워크플로우

`kospi-briefing` 잡의 `fetch_data.py` 직후에 스텝을 넣는다.
`continue-on-error: true` + `timeout-minutes: 5` — §21. 채점이 느리거나 실패해도 발행을 막지 않는다.
**렌더 단계에서 네트워크를 타지 않게 하는 것이 이 배치의 목적이다.**

## 실패 모드 — 전부 "섹션 생략"으로 수렴

| 상황 | 동작 |
| --- | --- |
| 어제 미국 브리핑 없음(휴장·발행 실패) | 섹션 생략 |
| 스냅샷에 `issues` 없음 | 섹션 생략 |
| 해당 ET 세션 봉이 아직 없음 | 그 티커 제외, 전부 없으면 카드 생략 |
| 결과 파일 날짜 불일치 | 무시 |
| 스크립트 실패·타임아웃 | `continue-on-error` — 브리핑은 정상 발행 |

**어느 경우에도 틀린 숫자를 보여주지 않는다.**

## 테스트

`scripts/test_us_issue_scoring.py` — 네트워크 없이 순수 함수를 검증한다.

- 판정 배지(전부 적중·부분·전부 빗나감), 결과 한 줄 조립(단수/복수/빗나감 문구)
- 중복 제거(같은 프록시·같은 방향 두 번째 카드는 결과줄 없음)
- 측정 불가 카드 생략, 전부 불가면 섹션 생략
- 날짜 게이트(세션 날짜 불일치 시 버림), 해당 날짜 봉 없을 때 최신 봉으로 폴백하지 않음
- **실사고급 리플레이** — 이번에 뽑은 9/3(3건 빗나감·1건 생략·중복 1건)과 9/4(4/4 적중) 실측
  데이터를 그대로 넣어 기대 출력과 대조한다.

## 범위 밖 / 알려진 리스크

- **채점 결과를 Claude에게 주지 않는다.** 주면 산문이 스코어보드와 어긋나는 걸 모델이 피할 수
  있지만 모델이 결과를 잘못 옮길 여지가 생긴다. 산문의 실측 모순은 §27·§22 게이트가 독립적으로
  잡으므로 v1은 렌더 전용으로 둔다.
- **07:25에 일봉이 확정돼 있는지는 배포 전에 확답할 수 없다.** 안 왔으면 섹션이 빠지는 안전한
  실패라 위험하진 않지만, 매일 빠지면 무용지물이다. 배포 후 며칠 로그로 확인하고, 상시 문제면
  분봉 기반으로 바꾸는 후속이 필요하다.
- 롱테일 라벨(13%)은 프록시를 늘리지 않는다. 매핑을 늘릴수록 추론이 늘어난다.
- 미국 브리핑 쪽 화면은 건드리지 않는다.
