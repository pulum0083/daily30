## 2. 러너 수집 가능 여부 — 실측으로 확인했다 (사용자 요청)

로컬(한국 IP)에서 되는 것과 GitHub Actions 러너(미국 데이터센터 IP)에서 되는 것은 다른
문제라, 일회성 워크플로우를 `ds-fng-check` 브랜치에 올려 러너에서 직접 호출했다.
([run 33349145885](https://github.com/pulum0083/daily30/actions/runs/33349145885), 확인 후 브랜치·파일 삭제)

| 조건 | 결과 |
| --- | --- |
| 러너 위치 | 172.183.135.246 · Chicago · AS8075 Microsoft(Azure) |
| 브라우저 헤더 있음 | **HTTP 200**, score 54.43 / neutral / 2026-08-28 종가 (로컬과 동일) |
| 헤더 없음 (대조군) | **HTTP 418** |

→ 수집 가능하다. 단 **User-Agent·Accept·Referer 헤더가 필수**다. 헤더를 지우면 418로
조용히 실패하고 행만 사라진다. `fetch_data.get_fear_greed()` 주석에 이 사실을 박아뒀다.

## 3. 표시 규칙

- 사이드바에는 **VIX + 공포·탐욕 지수 두 항목만**. 나스닥·필라델피아 반도체·나스닥100 선물
  행은 화면에서만 제거하고 **수집은 그대로 둔다** — `market_data_js`의 그 키들을
  `call_claude` 프롬프트·'지금 코스피' 밴드·다른 위젯이 계속 소비한다. 수집을 같이 줄이면
  분석 근거가 조용히 얇아진다(§36에서 `stocks.json`을 줄이려다 `fetch_movers_why`가
  같이 축소될 뻔한 것과 같은 함정).
- 등락은 %가 아니라 **포인트 차이(`-3.7p`)** 로 쓴다 — 0~100 점수라 등락률은 의미가 없다.
  `prev_close`가 없으면 `0.0p`로 채우지 않고 비운다(보합이라는 틀린 주장 방지).
- 뱃지 색은 기존 `vix-badge` 팔레트를 재사용한다. 공포·탐욕은 **양 끝이 모두 위험**이라
  극단(<25, ≥75)=red, 그 안쪽=yellow, 중립=green. CSS는 건드리지 않았다.
- 라벨은 CNN이 준 `rating`을 우선 쓰고, 없거나 모르는 값일 때만 점수 구간으로 되돌린다 —
  경계값(45·55·75)에서 CNN 표기와 어긋나지 않게.

## 4. 신선도 게이트 (§20·§32 계열)

수집이 조용히 죽으면 낡은 점수가 계속 진짜처럼 보인다. `_fng_is_fresh()`가 `asof`를 보고
**5일**보다 오래되면 행을 그리지 않고 stderr에 경고한다(3일 연휴+주말 버퍼). 시각이 없거나
파싱 실패해도 표시하지 않는다 — 완전성보다 정합성.

## 5. 모델에는 여전히 주지 않는다

`call_claude`의 [필수 규칙 5-1](공포탐욕지수 언급 금지)은 **유지**한다. 이 지수는
사이드바 표시용으로만 수집되고 프롬프트에는 들어가지 않으므로, 모델이 쓰는 수치는 어떤
것도 실측이 아니다. 규칙의 근거 문구만 현행화했다("수집되지 않는다" → "프롬프트에
주어지지 않는다"). 나중에 모델에게 주기로 한다면 그때 이 규칙을 함께 고쳐야 한다.
